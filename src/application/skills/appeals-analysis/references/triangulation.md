# 顾客洞察多源三角化规范

> $APPEALS 八维度评估的证据质量保障规范。每个维度的关键顾客洞察必须由 tavily /
> newsapi / china-nbs 全 3 个声明源交叉印证后方可作为评分依据。

## 1. 三角化原则

- **全源覆盖**：3 个声明源全部参与采集，任一维度不得仅凭单一来源下结论
- **独立性**：tavily（顾客洞察 Web 搜索）、newsapi（市场舆情）、china-nbs（中国消费统计）
  三类来源性质互异（个体声音 / 媒体叙事 / 官方统计），天然构成独立印证链
- **时效折算**：以 `freshness_score` 折算时效——newsapi（TTL 6 小时）适合捕捉即时舆情，
  tavily（TTL 24 小时）适合顾客讨论快照，china-nbs（TTL 24 小时，实际数据多为季度/年度）
  适合结构性消费趋势

## 2. 印证流程

1. 对八维度逐一提出候选顾客洞察（命题形式，如 "目标客群对 2000 元以上价格带接受度低"）
2. 在 3 源 payload 中分别检索支持/反驳证据，登记证据出处（来源 + 时间戳）
3. 三源一致支持 → 洞察成立（置信度高）；两源支持一源无数据 → 成立但标注覆盖缺口
4. 来源冲突 → 进入冲突裁决（§3）
5. 仅单源支持 → 洞察降级为「待验证假设」，写入 `customer_evidence` 时显式标注

## 3. 冲突裁决

| 冲突类型 | 裁决规则 |
|---------|---------|
| 个体声音 vs 官方统计 | 结构性结论以 china-nbs 为准；体验性结论以 tavily 为准，并标注差异 |
| 媒体舆情 vs 顾客讨论 | 以 tavily 一手顾客声音为准，newsapi 作为传播面佐证 |
| 时效冲突 | 以 `source_timestamp` 较新者为准，旧数据标注时效风险 |

## 4. 禁止事项

- 禁止以 LLM 先验知识替代采集证据充当「来源」
- 同一来源的多个 query（name/name#2 键）不构成独立来源，不得计入印证数
- 禁止在来源冲突时静默取其一而不标注
- 禁止将「无数据」表述为「顾客无此需求」
