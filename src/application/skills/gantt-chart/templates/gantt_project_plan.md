# 甘特图排程采集表格

> 工作坊现场填写；采集字段与 SKILL.md `input_schema` 一一对应（project_plan 为
> 嵌套分区，分区内字段即 Schema 叶子键）。校验规则见 `references/validation_rules.md`。

## 基本信息

| 字段 | 说明 |
| --- | --- |
| 项目名称 | 目标项目 |
| 排期周期 | 如 2026-Q4 |
| 工作坊日期 | 填写日期 |
| 引导者/记录员 | 名字 |

## 采集表格

### project_plan

| 字段 | 值 | 说明 |
| --- | --- | --- |
| tasks（必填） | 需求分析、架构设计、开发实现、里程碑评审、发布上线 | 任务名顿号分隔（禁含「、」与「←」以外的保留字符冲突——任务名本身禁含此二字符） |
| dependencies（必填） | 架构设计 ← 需求分析；开发实现 ← 架构设计 | 依赖边「任务名 ← 前置任务列表」（前置多个时顿号分隔），多条边以分号分隔 |
| durations（必填） | 需求分析＝5 天、架构设计＝2 周、里程碑评审＝0 天 | 外层键为任务名，值为「N 天/周/月」；「0 天」＝里程碑（零时长任务） |
| resources（必填） | 需求分析＝产品经理 1 人、开发实现＝后端 4 人 + 前端 2 人 | 外层键为任务名，值为资源投入描述（人员/设备/预算） |

> 逐项一行填写；时长格式必须匹配正则 `^\d+ *[天周月]$`（禁「个月」与英文单位；
> 归一基准＝天——周＝5 工作日、月＝20 工作日）；里程碑任务 durations 值写「0 天」。

## 校验规则

时长正则与归一基准、CPM 前推/后推（ES/EF/LS/LF 零浮动关键路径）、里程碑「0 天」
裁定、依赖边语法与 DAG 无环——逐条规则见 `references/validation_rules.md`。

## 数据缺口登记

| 字段 | 缺口描述 | 替代来源 |
| --- | --- | --- |
| durations | 开发实现时长历史基准缺失（新栈首用） | 技术负责人会后专项估算 |
| resources | 测试人力日历未确认（跨部门借用） | 资源经理协调记录 |
