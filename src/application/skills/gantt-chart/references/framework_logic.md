# 甘特图排程框架逻辑（CPM 系统化思考）

> 本 Skill 的分析主轴是「任务 × 依赖 × 时长」三要素到时间线的确定性推算：
> 时长归一到天基准后，前推（ES/EF）与后推（LS/LF）双向遍历依赖图，零浮动链
> 即关键路径。纯内部框架型：全部判断基于用户输入的项目计划，无外部印证。

## 系统化思考步骤（编号步骤序列）

- 步骤 1 —— 任务拆分粒度（tasks）：确认 project_plan.tasks 逐条为可交付、可验收
  的工作单元（8 小时-2 周粒度为宜）；里程碑单独列为任务（时长将编「0 天」），
  任务名禁含「、」与「←」（依赖边语法保留字符）
- 步骤 2 —— 依赖确认（dependencies）：逐任务追问「哪些前置不完成则本任务无法
  启动」——仅登记强依赖（完成-启动关系），弱关联（共享资源类）留给步骤 5 的
  资源冲突审视；依赖边编码「任务名 ← 前置任务列表」（顿号分隔）
- 步骤 3 —— 时长估算（durations）：逐任务估「N 天/周/月」（正则 `^\d+ *[天周月]$`，
  禁「个月」与英文单位）；估算法 = 三点估算（乐观 + 4×最可能 + 悲观）/ 6；
  归一基准＝天（周＝5 工作日、月＝20 工作日）后再参与算术
- 步骤 4 —— 里程碑锚定：将管控节点（评审/验收/发布）编码为 durations 值
  「0 天」的零时长任务（ES=EF）——里程碑是时间线上的检查点，不消耗工期
- 步骤 5 —— 资源冲突审视（resources）：对照 project_plan.resources 逐时段核对
  同期任务的资源占用（人员/设备/预算），识别超载时段并给出错峰或增援建议
  （LLM 分析项——非确定性规则，供 validation_rules 之外的判断输入）

## 填写指引

- tasks 与 dependencies 遵循 dependency-graph 同款任务名规范（禁含「、」与「←」）
- durations 为自由 object：外层键为任务名（须 ∈ tasks），值为时长串
- 里程碑规范写法「0 天」；非规范零时长（0 周/0 月）会被归一处理但模板统一写「0 天」
- resources 为自由 object：外层键为任务名，值为资源投入描述（人员/设备/预算）

## 聚合规则

- 前推（ES/EF）：ES = max(前驱 EF)（无前驱取 0），EF = ES + 归一时长
- 后推（LS/LF）：LF = min(后继 LS)（无后继取项目终点 EF），LS = LF - 归一时长
- 关键路径 = 零浮动（LS - ES = 0）任务的连通链（CPM 真关键路径——时长归一推算）
- 里程碑（0 天）仅当处于零浮动链才进入 critical_path，否则以 milestones 标记承载
