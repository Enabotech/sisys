# 依赖关系图确定性校验规则

> 结构型确定性规则 = 分析层评估逻辑：违规经输出结构化字段呈现（环违规经
> `dependency_network.dag` 的 cycles 键、引用缺失经 conflicts 说明），不映射为
> 运行时异常或 INSUFFICIENT_DATA。

## 逐条规则（编号规则序列）

- 规则 1 —— DAG 无环校验：依赖图不得存在有向环（Kahn 分层后未归零节点即成环）；
  环违规以 `dag.cycles` 结构化呈现（逐环列出任务名序列，如「需求分析 → 技术选型 →
  需求分析」），引导澄清依赖方向后重跑，非整体失败
- 规则 2 —— 依赖方向规则：dependencies 仅引用 task_list 中已登记的任务名；引用
  不存在任务名（前向/悬空引用）登记为引用缺失冲突，逐条列出缺失名
- 规则 3 —— 关键路径推算（跳数最长链）：critical_path = 跳数最长链的无时长
  结构代理（输入无工期时的退化形态——与 gantt-chart 的时长归一真 CPM 语义分工：
  dependency-graph 输入无 durations，gantt-chart 以 ES/EF/LS/LF 零浮动推算；
  需要真关键路径时先经 gantt-chart 补工期）
- 规则 4 —— risk_nodes 判定（机械规则）：扇入 ≥3 的汇聚节点（多前置汇合瓶颈）、
  扇出 ≥3 的发散节点（单一前置阻塞大量后继）与零依赖/零被依赖的孤立节点
  （疑似漏登记或范围外任务）自动入列；其余风险判断
  （关键人依赖/外部供应商依赖）为 LLM 分析项，不入 risk_nodes
- 规则 5 —— 任务名字符约束：任务名禁含顿号「、」与箭头「←」（正则校验——顿号
  是模板行内前置列表分隔符、← 是依赖边语法符号，混入即产生解析歧义）；违规任务名
  逐条列出并要求改名后重跑

## 输出通道

| 规则违规 | 结构化出口 | 处置语义 |
| --- | --- | --- |
| 规则 1 环 | `dependency_network.dag.cycles` | 澄清依赖方向后重跑 |
| 规则 2 引用缺失 | `dependency_network.dag` 引用缺失清单 | 补登记任务或修正引用 |
| 规则 3 并列链 | `critical_path` 全列 + 并列标注 | 并列链全部呈现 |
| 规则 4 风险节点 | `risk_nodes` | 机械命中，逐节点说明类型 |
| 规则 5 非法字符 | 引用缺失清单同区呈现 | 改名后重跑 |
