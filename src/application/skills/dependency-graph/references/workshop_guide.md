# 依赖关系图梳理工作坊引导（2-4 小时结构化）

> 纯内部框架型工作坊：无外部数据采集环节，以用户结构化输入工作坊替代——
> 全部判断基于项目计划的内部事实现场对齐。

## 会前准备（T-3 天）

| 时点 | 动作 | 产出 |
| --- | --- | --- |
| T-3 天 | 分发 `templates/dependency_task_inventory.md` 与预填指引给业务专家 | 各自预填任务草稿（不汇总，防锚定） |
| T-2 天 | 收集 WBS 旧表、里程碑计划、跨团队接口清单等内部材料 | 材料清单 |
| T-1 天 | 引导者汇总任务名速览（标题级，不预判依赖） | 速览页 |

## 现场流程（2-4 小时）

| 环节 | 时长 | 产出物 |
| --- | --- | --- |
| 开场与规则宣讲 | 15 min | 纪律共识（防锚定/防溢出） |
| 任务穷尽性盘点 | 40 min | name 清单定稿（全链条覆盖） |
| 逐任务依赖确认 | 60 min | dependencies 逐任务登记（硬依赖仅入） |
| 并行分组预演（拓扑分层） | 30 min | 同层并行分组草图 |
| 风险节点与缺口登记 | 30 min | 模板定稿（含缺口登记区） |

## 时间压缩指引（2 小时精简变体）

| 环节（精简版） | 时长 | 说明 |
| --- | --- | --- |
| 开场与规则宣讲 | 15 min | 纪律宣讲不可压缩 |
| 任务盘点 + 依赖确认合并 | 70 min | 逐交付物牵引任务与依赖同步确认，任务上限 12 条 |
| 并行分组与缺口登记 | 35 min | 仅核扇入 ≥3 汇聚节点 |

- **压缩代价**：依赖确认深度下降，被裁核对项转入缺口登记区会后补齐
- **不可压缩项**：任务名字符约束宣讲、硬/软依赖区分、缺口登记——省略即失效

## 角色分工

- **引导者**：控流程/控时/执行纪律，不参与内容判断
- **业务专家**（2-4 人，含项目经理与各职能代表）：任务提出与依赖确认主体
- **记录员**：实时填写模板表格（name 单任务名 + dependencies 顿号分隔），逐条登记缺口

## 引导纪律

- **防锚定**：预填草稿开场后才同时公开；任务盘点先于依赖确认（防从依赖反推任务清单）
- **防过密**：仅硬依赖入图（不做完不能开始）；软依赖（顺序偏好）登记备注不进 dependencies
- **防溢出**：单任务依赖讨论超 5 分钟即登记「待议」移入缺口登记区
- 每任务必须落到模板行（name/dependencies/证据来源三列齐全才算完成）

## 会后跟进

1. 记录员 24h 内回收定稿模板，补齐缺口登记区的替代来源
2. 按模板「采集表格」字段构造 `ToolCall.arguments` 参数（模板→arguments 构造闭环）：
   `task_list`（对象数组——每任务 `{"name": 任务名, "dependencies": [前置任务名数组]}`，
   顿号分隔形态转写为数组、无前置转写为空数组）
3. 调用本 Skill 执行：Agent 构建 DAG 并输出 dependency_network（critical_path =
   跳数最长链结构代理 + risk_nodes 机械命中清单）
4. 结果回传业务专家确认（重点：环违规处置与孤立任务是漏登记还是范围外）
