# 依赖关系图拓扑分析框架逻辑

> 本 Skill 的分析主轴是「任务清单 → 有向无环图（DAG）→ 拓扑结构洞察」：依赖关系
> 是纯粹的结构事实（谁挡谁），不含时间维度（工期/排程属 gantt-chart）。纯内部
> 框架型：全部判断基于用户输入，无外部印证。

## 系统化思考步骤（编号步骤序列）

- 步骤 1 —— 任务穷尽性检查（task_list）：核对 name 清单是否覆盖交付物全链条
  （从启动到验收）；遗漏任务会在依赖图中表现为孤立断链，逐一确认是「真无依赖」
  还是「漏登记」
- 步骤 2 —— 依赖方向确认（dependencies）：逐任务确认前置关系——依赖边方向 =
  「前置完成 → 本任务可启动」；区分硬依赖（不做完不能开始）与软依赖（仅顺序
  偏好），软依赖不进 dependencies（防图过密掩盖真约束）
- 步骤 3 —— 层级归整（拓扑分层）：按入度归零法分层（Kahn 算法）——同层任务
  无相互依赖可并行；层数 = 最长链跳数的结构骨架
- 步骤 4 —— 扇入扇出异常识别（risk_nodes）：标记三类机械异常——扇入 ≥3 的汇聚
  节点（多线汇合的瓶颈位）、扇出 ≥3 的发散节点（单一前置阻塞大量后继）与
  零依赖/零被依赖的孤立节点（疑似漏登记或范围外任务）；
  其余风险判断（如关键人依赖）为 LLM 分析项，登记于输出说明而非 risk_nodes
- 步骤 5 —— 关键路径推算：critical_path = 跳数最长链的无时长结构代理——在无
  工期输入下以「经过任务数最多」的链路近似关键路径（结构代理，见 validation_rules
  规则 3 与 gantt-chart 的语义分工）

## 填写指引

- 逐任务一行：模板采集表格中每任务一组行（name 单任务名 + dependencies 前置
  任务列表——模板行内以顿号「、」分隔，如「需求分析、技术选型」）
- 任务名字符约束：禁含顿号「、」与箭头「←」（防分隔歧义与依赖边语法冲突）
- 无前置任务：dependencies 填「无」，记录员转写为空数组（显式空表）
- 依赖边编码：任务名 ← 前置任务列表（解析端按 name 精确匹配任务名）

## 聚合规则

- 拓扑分层（Kahn）产生并行分组；同层任务数 = 并行度上界
- critical_path 取跳数最长链（并列多条时全部列出，标注并列）
- dependency_network.dag 以邻接表承载图结构；环违规以 cycles 键结构化呈现
  （逐环列出任务名序列），不映射运行时异常
