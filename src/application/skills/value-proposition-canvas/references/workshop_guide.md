# 价值主张画布工作坊引导（2-4 小时结构化）

> 纯内部框架型工作坊：无外部数据采集环节，以用户结构化输入工作坊替代——
> 全部判断基于客户访谈事实与产品事实的现场对齐。

## 会前准备（T-3 天）

| 时点 | 动作 | 产出 |
| --- | --- | --- |
| T-3 天 | 分发 `templates/vpc_canvas_matching.md` 与预填指引给业务专家 | 各自预填草稿（不汇总，防锚定） |
| T-2 天 | 收集客户访谈记录、客诉台账、产品路线图等内部材料 | 材料清单 |
| T-1 天 | 引导者汇总客户侧条目速览（标题级，不预判匹配） | 速览页 |

## 现场流程（2-4 小时）

| 环节 | 时长 | 产出物 |
| --- | --- | --- |
| 开场与规则宣讲 | 15 min | 纪律共识（防锚定/防从众） |
| 客户任务逐条评审（jobs） | 30 min | jobs 清单 + 重要性分值 |
| 痛点深挖（pains） | 30 min | pains 清单 + 严重度分值 |
| 收益提炼（gains） | 30 min | gains 清单 + 重要性分值 |
| 价值图铺设（三块并行） | 45 min | products / pain_relievers / gain_creators 清单 + 匹配强度分值 |
| 三对匹配预演与缺口登记 | 30 min | 模板定稿（含缺口登记区） |

## 时间压缩指引（2 小时精简变体）

| 环节（精简版） | 时长 | 说明 |
| --- | --- | --- |
| 开场与规则宣讲 | 15 min | 纪律宣讲不可压缩 |
| 客户侧三块连续评审 | 50 min | jobs→pains→gains 连续，每块条目上限 4 条 |
| 价值图三块连续铺设 | 40 min | 按三对镜像逐块回应，每块上限 3 条 |
| 匹配预演与缺口登记 | 15 min | 仅核对最弱一对 |

- **压缩代价**：条目深度下降，被裁条目转入缺口登记区会后补齐
- **不可压缩项**：防锚定纪律宣讲、双侧分值独立评定、缺口登记——省略即失效

## 角色分工

- **引导者**：控流程/控时/执行纪律，不参与内容判断
- **业务专家**（2-4 人，含客户侧与产品侧代表）：条目提出与评分主体
- **记录员**：实时填写模板表格，逐条登记证据与缺口

## 引导纪律

- **防锚定**：预填草稿开场后才同时公开；jobs 先于 pains/gains 评审（分析起点，防从痛点反推任务）
- **防从众**：分值采用先独立举牌后讨论收敛；职级不参与评分权重
- **防溢出**：单条目讨论超 5 分钟即登记「待议」移入缺口登记区
- 每条目必须落到模板行（字段/分值与描述/证据三列齐全才算完成）

## 会后跟进

1. 记录员 24h 内回收定稿模板，补齐缺口登记区的替代来源
2. 按模板「采集表格」字段构造 `ToolCall.arguments` 参数（模板→arguments 构造闭环）：
   `customer_profile.{jobs, pains, gains}` / `value_map.{products, pain_relievers, gain_creators}`
   （每条携带分值与描述，供 Agent 解析匹配强度并计算木桶聚合）
3. 调用本 Skill 执行：Agent 基于框架逻辑生成 fit_assessment（fit_score = 三对最小值）
4. 结果回传业务专家确认（重点：构成最小值的最弱一对是否需要产品侧补强）
