# RACI 矩阵确定性校验规则

> 本文件承载 RACI 矩阵的确定性评估逻辑（分析层规则）——违规经输出根键
> `raci_matrix.conflicts` 结构化呈现（逐任务违规条目），**不映射为运行时异常、
> 不触发整体失败、不产生 INSUFFICIENT_DATA 状态**。

## 规则清单（逐条编号）

- 规则 1 —— 恰 1 个 A（硬规则）：每个任务（assignments 外层键）有且仅有一个
  Accountable——统计该任务全部内层值中含字母 A 的组合数（A 或 A/R 等斜线组合），
  计数 ≠ 1 即违规。多 A → 冲突条目「任务 X：问责稀释（A × N）」；零 A →
  「任务 X：问责真空」。RACI 单点问责原则的机械判定。
- 规则 2 —— ≥1 个 R（软规则）：每个任务至少有一个执行承担者——内层值中
  R 字母计数 ≥1；**A/R 组合计为已承担 R**（业界「问责者兼执行」兼任惯例），
  即含 R 的斜线组合均计入。软规则违规同样汇入 conflicts（冲突条目格式
  「任务 X：R 缺失（软规则）」），不阻断输出。
- 规则 3 —— 无空任务：tasks 数组中每个任务名必须在 assignments 有对应外层键
  且该键的内层字典非空；缺失或空字典 → 冲突条目「任务 X：未分配」。反向的
  assignments 多余键（不在 tasks 中）同样登记。
- 角色名一致性（规则 3 延伸）：assignments 内层键必须 ∈ roles 数组——未知角色
  名登记冲突条目「任务 X：角色 Y 未在 roles 声明」。
- 规则 4 —— 字母组合语法：每个内层值为单字母（R/A/C/I）或**两字母不重复**
  斜线组合（如 A/R，字母次序不限——A/R 与 R/A 为同一组合）；三字母及以上组合、
  出现非法字母（如 X）、重复字母（如 A/A）或非斜线分隔符 → 冲突条目「任务 X /
  角色 Y：非法组合」。正则形态 `^(R|A|C|I|R/A|A/R|R/C|C/R|R/I|I/R|A/C|C/A|A/I|I/A|C/I|I/C)$`。
- 规则 5 —— 违规出口：全部确定性规则违规统一汇入 `raci_matrix.conflicts`
  （array[string]，逐任务逐角色分列）；输出整体仍为成功——冲突呈现是分析结论
  的一部分，供工作坊复议修正后重跑。

## 判定顺序与示例

1. 先语法（规则 4）后语义（规则 1/2/3）：非法组合先登记，再以合法条目计算
   A/R 计数（非法条目不参与计数）
2. 示例：「需求分析」内层 {产品经理: A/R, 架构师: C} → A 计数 1（A/R 含 A）、
   R 计数 1（A/R 计为已承担 R）→ 规则 1/2 均通过
3. 示例：「系统测试」内层 {测试负责人: A, 开发负责人: R} → A 计数 1、R 计数 1
   → 通过；若再增 {产品经理: A} → A 计数 2 → 规则 1 冲突（问责稀释）
