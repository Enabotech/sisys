# RACI 矩阵职责分配框架逻辑

> 本 Skill 的分析主轴是「任务 × 角色」的职责二维分配：R（Responsible 执行）、
> A（Accountable 问责）、C（Consulted 咨询）、I（Informed 知会）四类字母在
> 矩阵单元格中的组合。纯内部框架型：全部判断基于用户输入的角色分工事实。

## 系统化思考步骤（编号步骤序列）

- 步骤 1 —— 任务穷举（tasks）：从流程/项目分解出任务清单（tasks 数组），逐条确认
  任务表述是「可问责的交付动作」而非状态描述（「完成设计评审」而非「设计中」）
- 步骤 2 —— 角色映射（roles → assignments）：对每条任务逐角色判定职责字母——
  谁执行（R）、谁对结果负最终责任（A）、谁须被咨询（C）、谁须被知会（I）；
  判定结果落入 assignments 双层结构（外层键为任务名，内层键为角色名）
- 步骤 3 —— 单点问责检查（恰 1 A）：逐任务核对 Accountable 有且仅有一个
  （assignments 外层键 = 检查粒度）——多 A 即问责稀释、零 A 即问责真空，
  两种均登记 conflicts
- 步骤 4 —— 负载均衡审视（≥1 R 与分布）：逐任务确认至少一个承担者（A/R 组合
  计为已承担 R——业界兼任惯例）；再横向审视 R 的分布——单角色 R 过载（如 >60%
  任务）生成 suggestions（负载再平衡方向）
- 步骤 5 —— 缺口识别与建议：汇总 conflicts（确定性规则违规）与 suggestions
  （负载/问责优化），输出规整化 raci_matrix

## 填写指引

- 双层编码记法：任务名→角色名＝RACI 字母组合（单字母 R/A/C/I 或斜线组合如 A/R）；
  assignments 外层键为任务名（与 tasks 一致），内层键为角色名（与 roles 一致）
- 工作坊现场先在矩阵速查表（任务为行、角色为列）中讨论，定稿后逐格转录为双层
  编码——矩阵单元格与 assignments 内层键值一一对应
- 一个单元格可填斜线组合（如 A/R 表示同一角色既问责又执行）；空白单元格表示
  该角色对该任务无职责（无需显式填写 I）
- 角色名与任务名保持与 roles/tasks 数组逐字一致（比对依据）

## 聚合规则

- 规则判定逐任务进行（外层键粒度），违规清单汇入 raci_matrix.conflicts
- 确定性规则（恰 1 A / ≥1 R / 无空任务 / 字母语法）见 validation_rules.md——
  违规经 conflicts 结构化呈现，不触发整体失败
- suggestions 由 LLM 分析层生成（负载均衡、单点问责改善方向）——非确定性规则，
  不进入 conflicts
