# PESTEL 工作坊引导方法论

> 适用：战略团队 2-4 小时 PESTEL 研讨工作坊。本工具输出作为工作坊的数据输入，
> 工作坊产出作为 SP 市场洞察阶段的共识结论。

## 会前准备（T-3 天）

1. 明确议题：行业 / 地域 / 年限三要素（对齐 input_schema 必填字段）
2. 运行本工具完成数据采集与初评（产出六维度评分 + 溯源元数据）
3. 将 `templates/pestel_collection_matrix.md` 打印/投屏，预填工具采集的指标观测值

## 工作坊流程（120-240 分钟）

| 阶段 | 时长 | 活动 | 产出 |
|------|------|------|------|
| 1. 开场 | 10' | 引导师说明议题、规则、产出物 | 议程共识 |
| 2. 数据回顾 | 30' | 逐维度展示采集数据与评分依据（含 freshness/confidence） | 数据共识 |
| 3. 分组研讨 | 60' | 六维度分组挑战评分：证据是否充分？三角化是否成立？ | 评分调整记录 |
| 4. 全体合议 | 40' | 逐维度确认最终评分，记录分歧与裁决理由 | 六维度共识评分 |
| 5. 机会威胁排序 | 30' | 按评分 × 影响度排序 Top3 机会 / Top3 威胁 | O/T 清单 |
| 6. 收尾 | 10' | 确认后续行动（输入 SWOT-TOWS / 情景规划） | 行动项 |

## 角色分工

- **引导师**：控场、确保数据驱动讨论（禁止无数据支撑的纯观点）
- **记录员**：填写采集矩阵模板，登记评分调整与理由
- **维度 Owner**：每组 1 人，负责该维度证据陈述
- **挑战者**：专职质疑三角化充分性（"这个结论有几个独立来源？"）

## 引导话术

- 评分争议时：「我们回到数据——这个维度的 3 个来源分别显示了什么？」
- 数据缺口时：「这个维度缺 X 源印证，我们是标注置信度下调，还是会后补采？」
- 超时预警：「当前维度还剩 5 分钟，请聚焦评分与关键证据」

## 会后跟进

- 共识评分回填 `aggregate_scores.py` 重新聚合（如与工具初评有调整）
- 数据缺口登记到数据源治理清单（评估是否需新增适配器）
