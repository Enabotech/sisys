## 💡 关键教训

### 核心教训

> **"随着开发交付件越来越多，重构难度越来越大"**

### 根本原因分析

| 问题 | 原因 | 影响 |
|------|------|------|
| 测试框架先行，领域代码滞后 | Story 0.3 建立测试框架，但领域基类在 P1 阶段才创建 | 测试写了但无法运行，重构时没有保护网 |
| 大部分测试未遵循 TDD 循环 | SDD+TDD 融合模式在 Epic 0 结束时才确立 | 测试作为"验证工具"而非"设计驱动" |
| 缺乏测试保护网 | 没有红 - 绿 - 重构循环 | 每次修改都变得困难，重构风险高 |

### 改进措施

**SDD+TDD 融合模式：**
- SDD 规范驱动 - 保证方向正确（Schema/API 契约/验收标准）
- TDD 测试驱动 - 保证实现正确（红 - 绿 - 重构循环）
- Qwen Code Agent 智能辅助 - 提升开发效率

**开发流程演变：**
```
初始模式（Epic 0 开始）:
规范定义 → 代码实现 → 测试验证

融合模式（Epic 0 尾声）:
规范定义 → TDD 红 - 绿 - 重构循环 → SDD 规范验证
```
