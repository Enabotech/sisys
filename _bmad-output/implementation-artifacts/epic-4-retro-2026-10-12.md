## 二、成功亮点

### 2.1 五轮循环审查工作流完全成熟

C1(多视角调研)→C2(方案)→C3(双评审门禁)→C4(提交)→C5(循环)——从 4-1b 第二周期成型，成为全 Epic 标准工作流。R5 独立终审「不轻信自报」五节取证（周期闭合/双向取证/独立快扫/门禁实跑/状态流转）是质量最大保障。沉淀为项目记忆 `review_loop_workflow_pattern`。

### 2.2 突变实证取代纸面验证

从 4-1c「变异演示」到 4-1f/4-5/4-6/4-7「突变注入-还原闭环」（改坏→跑→应红→还原），恒真断言从「靠运气发现」变为「机械检出」。4-7 五轮清偿 P1×6 + P2×10 + P3×18 全部经突变验证判别力。

### 2.3 断言覆盖矩阵与守护面意识

「守护面滞后于内容面」成为独立缺陷类别（4-1f Q3 先例）。新行为契约交付时逐项标注 file:line 断言覆盖，4-7 的断言覆盖矩阵是范本。

### 2.4 真实运行验证（PESTEL 全链）

五阶段引擎 + Docker 沙箱 + UDMR 云端 LLM（MiniMax-M3）真实执行成功——产出完整的电动汽车产业 PESTEL 六维度评分报告（加权 0.715 / 机会主导）。虽经历 13 轮调试暴露 5 层引擎缺陷，但证明了「mock 下的工程成熟度可以转化为真实可执行」。

### 2.5 UDMR SSOT 接线（回顾会期间完成）

审计发现「统一走 UDMR」是愿景非事实（双轨配置 + 休眠 handler + 引擎非标调用）→ 6 项修复（F1 SSOT 接线 / F2 handler 激活 / F3 引擎 generate() / F4 技债登记 / F5 env 收敛 / F6 超时）→ 「配置 UDMR_CLOUD_* 即生效」从愿景变为代码事实。

## 三、挑战与痛点

### 3.1 事件零发布/装配断线贯穿全 Epic（A1/A3 模式）

6 个 Story 出现事件「注册了但未发布」或「实现了但未接线」（4-3 核心价值未装配 P0 / 4-6 三事件零发射 / 4-5 metadata UUID 炸双通道 / 4-7 SessionMiddleware 休眠）。**Epic 5 行动项：链路接线断言设为每 Story Task 0 固定项。**

### 3.2 恒真断言是最大测试隐患

8/13 Story 存在恒真断言/自证测试/假锚点（P0 级 3 处）。变异实证已制度化为解药，但首个 Story 仍需付出学费。**Epic 5 行动项：新断言必做变异演示写进 DoD。**

### 3.3 mock 与真实的鸿沟（~24 个测试文件连锁更新）

F3 引擎修复（structured_generate→generate）引发 24 个测试文件 mock 连锁更新——mock 按方法名/返回形态绑定，方法签名变更时爆炸半径不可控。**教训：mock 绑定应基于行为契约（prompt 前缀），非实现细节（方法名/返回类型）。**

### 3.4 跨轮遗忘（A5 模式）

4-1b F9 留项跨三轮丢弃 → Deferred→4.7 单一清单表制度化。deferred-work.md + 触发条件时间线（本次回顾会产出）是最终形态。

### 3.5 文档审查整改量大但价值也大

单 Story 文档审查达 60+ 项修正；4-6 三个 P0 全是「标题功能不可实现」（状态机矛盾/终身死锁）——在实施前拦截。可满足性推演（场景期望唯一性/时间线终态/Task 依赖干跑）是文档审查最高价值面。

## 六、关键洞察

1. **mock 与真实的鸿沟是系统性风险** — 10,891 mock 测试全绿 ≠ 真实可用。PESTEL 13 轮调试暴露的 5 层缺陷全部在 mock 覆盖之外。真实 LLM 烟雾测试应成为每个新引擎功能的验收门禁。

2. **「配置了但未生效」是最隐蔽的架构债** — UDMR 双轨配置存在于两个 Epic 而无任何技术债登记。审计发现时已积累 3 个 Story 的误导。所有「已实现但未接线」组件必须在 deferred-work.md 登记。

3. **审查质量本身需要审查** — 从「修 bug」→「修守护」→「突变实证守护真实性」的进化路径，证明测试质量本身是被测对象。

4. **文档审查的最高价值是「可满足性推演」** — 4-6 三个 P0 均为「规范级不可实现」（状态机矛盾/终身死锁），在代码前拦截的成本远低于代码后发现。

5. **枚举加值类变更须全仓 grep 断言位** — 4-7 R4 纯验证轮抓出 4-1a 遗漏的枚举边界联动。给 Epic 5 最实用的单条纪律。
