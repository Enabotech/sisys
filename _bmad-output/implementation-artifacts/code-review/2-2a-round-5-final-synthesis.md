## 二、业界最佳实践对标

### 总体架构评分: 66/100

| 维度 | 得分 | 评语 |
|------|------|------|
| 六边形架构 | 95/100 | 端口定义干净，DI 正确，分层严格 |
| Async I/O 模式 | 50/100 | `tmp.write(chunk)` 同步阻塞事件循环，aiofiles 已安装但未使用 |
| OWASP 文件上传安全 | 40/100 | 无魔术字节校验，仅扩展名白名单，无病毒扫描 |
| API 设计 (Textract/Azure 对标) | 60/100 | 缺少请求边界校验、页面范围参数、速率限制 |
| Python 最佳实践 | 75/100 | frozen dataclass/Protocol 使用正确，但有方法内 import、无并发控制 |

### Top 5 与业界标准的关键偏离

1. **同步文件 I/O 在 async 上下文中** (CRITICAL) — `_download_to_temp:159` `tmp.write(chunk)` 阻塞事件循环
2. **无内容级 MIME 校验** (CRITICAL) — 仅扩展名白名单，攻击者可重命名 ZIP 炸弹为 .pdf
3. **下载前无大小检查** (HIGH) — 整个文件从 MinIO 下载完毕后才由解析器校验大小
4. **无并发/内存预算控制** (HIGH) — 10 并发 × 100MB PDF = 1GB+ 内存风险
5. **编码检测仅覆盖 CJK** (HIGH) — UTF-8/GBK/GB18030 硬编码，ISO-8859-1/Shift-JIS 等会静默损坏

### 风险矩阵

| # | 问题 | 风险等级 | 修复成本 |
|---|------|---------|---------|
| 1 | 同步文件写入 async 上下文 | 高 | 低 (使用 aiofiles) |
| 2 | 无魔术字节 MIME 校验 | 高 | 低 (添加 python-magic) |
| 3 | 下载前无大小检查 | 高 | 中 (添加元数据检查) |
| 4 | 无并发/内存控制 | 中 | 中 (添加 asyncio.Semaphore) |
| 5 | 编码检测范围过窄 | 中 | 低 (添加 charset-normalizer) |
| 6 | `__import__()` DI 模式脆弱 | 低 | 低 (使用标准导入) |
| 7 | TextParser 无换行符规范化 | 低 | 低 (单行正则修改) |
