## Executive Summary

### Project Vision

**sisys** 是面向大中型企业高管团队、企业战略与市场体系人员和专业顾问的 AI 驱动战略规划与决策智能平台。系统的核心使命是**让战略规划（SP）到业务执行（BP）的闭环变得可见、可验证、可信赖**。

**为什么是 SP↔BP 闭环？**

企业战略管理最大的失败不是"没有规划"，而是**规划与执行之间的断裂**——SP 做完了锁进抽屉，BP 另起炉灶另搞一套。sisys 借鉴华为 DSTE（开发战略到执行）20 年验证的方法论，通过 BLM（业务领先模型）+ BEM（业务执行力模型）双引擎，将 SP 到 BP 深度咬合，形成 **"方向—解码—执行—反馈"** 的完整闭环：

> **SP 把控方向与节奏，BP 落实推进业务执行。** 这是 sisys 在战略管理中不可替代的独特价值，也是企业从"规划"走向"作战"的核心枢纽。

**战略管理体系构建：**

系统的 UX 设计围绕一个核心问题展开：**如何让用户清晰看到战略管理切实可行？**

| 信任节点 | 用户内心的疑问 | UX 必须回答 | DSTE 方法论支撑 |
|---------|---------------|------------|---------------|
| **SP 置信度** | "AI 定的这个方向真的对吗？凭什么？" | 看见证据链——数据来源、推导逻辑、多 Agent 辩论、被否决的替代方案 | BLM 市场洞察三定 + 红蓝对抗 + CSP 蓝军专题 |
| **BP 置信度** | "SP 的战略意图被准确翻译成 BP 了吗？有没有失真？" | 追溯映射关系——每个 BP 举措对应 SP 哪个战略控制点，KPI 如何从 CSF 逐级导出 | BEM 六步法 + 三次战略解码 |
| **EM 置信度** | "这个计划真能落地吗？资源够吗？风险可控吗？" | 验证可行性——资源约束检查、里程碑校验、偏差预警、历史对比基准 | 经营分析会 + 战略健康度 + PBC 承诺管理 |

**核心价值主张：**

| 用户群体 | 核心价值 | 信任焦点 |
|---------|---------|---------|
| **高管团队** (CEO/CFO/CTO 等) | 通过 AI 协作在几天内达成战略共识；30 秒理解方向是否可信、执行是否存在风险 | SP 置信度 + EM 置信度 |
| **企业战略与市场体系人员** | 标准化 SP→BP 全流程，每个 BP 举措可追溯至 SP 战略控制点，消除解码失真 | BP 置信度 + SP 置信度 |
| **专业顾问** | 3 小时完成原本需要 1 天的分析报告，白标输出 + 溯源验证，客户信服 | 全链条信任 |

### Target Users

**sisys 服务三类核心用户群体：**

| 用户类型 | 代表人物 | 核心需求 | 使用频率 |
|---------|---------|---------|---------|
| **高管团队** | CEO 张总、CFO 王总 | 快速战略共识、财务量化决策、风险全景视图 | 低（周/月） |
| **企业战略与市场人员** | 李经理、小刘、小陈 | 流程标准化、高保真溯源、报告自动生成 | 高（日/周） |
| **专业顾问** | 王经理（咨询）、赵经理（投资） | 白标输出、多租户隔离、项目交付效率 | 中（项目周期） |

**用户优先级：** MVP 阶段优先服务**企业战略与市场人员**（高频用户），同时提供**高管决策视图**（付费决策者）。

### Key Design Challenges

基于多方视角讨论，识别以下关键 UX 设计挑战：

1. **三页面驾驶舱导航一致性** - 如何在决策舱（战略推演+AI代偿）、工作台（证据树+辩论追溯）、战略地图（BSC四层瀑布流）三页面之间保持流畅导航和数据联动，同时通过角色自适应视图匹配差异化决策深度？

2. **多 Agent 协作可视化** - 如何将抽象的 AI 多角色辩论过程以直观、可理解的视觉方式呈现？

3. **高保真溯源体验** - 如何实现从结论到原始文档坐标点的精准跳转，同时保持流畅的交互体验？

4. **合规与简洁的平衡** - 如何在满足 SOX/ISO27001 合规要求的同时，为高管用户提供简化决策体验？

5. **信息密度差异化** - 高管视图需要低信息密度（30 秒决策），专业人员视图需要高信息密度（深度分析）

6. **SP 置信度挑战** - 如何让高管相信 AI 分析出的战略方向比人工判断更优？市场洞察证据如何组织？被否决的替代方案如何呈现？

7. **BP 置信度挑战** - 如何让用户看到 SP→BP 的翻译过程没有失真？数百条 BP 举措如何与上游 SP 战略控制点建立可追溯的映射？

8. **EM 置信度挑战** - 如何让用户相信计划切实可行？资源约束、里程碑设定、风险预案如何可视化校验？

---

### Design Opportunities

基于竞争分析和用户痛点，识别以下设计机会：

1. **SP 置信度证据链** - 打造"市场洞察"证据面板（市场/客户/竞争/技术/自身），展示多 Agent 辩论过程与被否决的替代方案，成为碾压性竞争优势

2. **溯源交互创新** - Bounding Box 级溯源可成为行业标杆体验，作为战略管理的技术基础设施

3. **白标品牌定制** - 为咨询/投行用户提供完全可定制的品牌体验，增强专业感

4. **财务量化可视化** - 敏感性分析龙卷风图、情景对比滑块等创新交互，服务EM 置信度

5. **SP→BP 解码透视图** - 三层解码层级透视图（公司→部门→岗位）+ SP 控制点→BP 举措逐条映射，建立解码信任

6. **执行可行性校验** - 资源约束检查 + 里程碑合理性验证 + 偏差预警机制，让用户相信计划可落地

## Core User Experience

### Defining Experience

**核心用户体验定义：**

sisys 的核心用户体验是 **SP 把控方向与节奏，BP 落实推进业务执行**。这不是一条进度条能承载的——它需要三个独立的信任构建层，每一层回答用户心中一个根本问题：

```
┌────────────────────────────────────────────────────────────────┐
│                                                                │
│  层3: EM 置信度 — "这个计划真能落地吗？"                         │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │ 资源约束仪表盘 │ 里程碑校验 │ 偏差预警 │ 历史对比基准      │  │
│  └──────────────────────────────────────────────────────────┘  │
│                              ↑                                 │
│  层2: BP 置信度 — "SP→BP 的翻译有没有失真？"                     │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │ SP控制点→BP举措映射 │ 三次解码透视图 │ KPI锚点追溯          │  │
│  └──────────────────────────────────────────────────────────┘  │
│                              ↑                                 │
│  层1: SP 置信度 — "AI 定的这个方向真的对吗？"                     │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │ 市场洞察证据面板 │ 多Agent辩论可视化 │ 被否决替代方案            │  │
│  └──────────────────────────────────────────────────────────┘  │
│                              ↑                                 │
│  基础: 高保真溯源 — Bounding Box 跳转 + 置信度 + 数据血缘        │
│  (技术手段，为三层信任提供数据层面的可验证性)                     │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```

**用户旅程的关键节点（重构后）：**

```
1. 上传数据（17 种格式） → 2. 自动解析 → 3. 多 Agent 协作分析 → 4. 方向验证（市场洞察面板）
         ↓
5. 高管确认方向 → 6. SP→BP 战略解码 → 7. 解码追溯验证 → 8. 执行计划校验
         ↓
9. 财务量化 → 10. 偏差预警设置 → 11. 执行追踪 → 12. 复盘反馈
```

**最关键的交互（必须完美）：**

| 交互 | 用户 | 期望体验 | 所属信任层 |
|------|------|---------|-----------|
| **方向验证** | CEO 张总 | 展开市场洞察证据面板，查看多 Agent 辩论，理解"为什么这个方向是对的" | SP 置信度 |
| **解码追溯** | 李经理（战略） | 点击 BP 举措 → 追溯上游 SP 战略控制点 → 查看解码依据 | BP 置信度 |
| **执行校验** | CFO 王总 | 每个计划自动显示资源约束状态 + 里程碑合理性 + 风险标注 | EM 置信度 |
| 高保真溯源 | 李经理（战略） | 30 秒内从结论跳转至原始文档坐标点 | 信任基础设施 |
| 高管审批 | CEO 张总 | 30 秒内理解态势并做出决策 | SP 置信度 + EM 置信度 |
| 财务量化 | CFO 王总 | 每个战略建议自动显示 NPV/IRR/敏感性分析 | EM 置信度 |
| 白标报告 | 王经理（顾问） | 一键生成符合品牌规范的 PPT/PDF | 全链条信任 |
| 批量筛选 | 赵经理（投资） | 2 小时内完成 100 个项目初筛 | SP 置信度 |

### Platform Strategy

**平台策略决策：**

| 决策 | 选择 | 理由 |
|------|------|------|
| **主要平台** | Web 应用（响应式） | 企业用户主要在桌面端使用，支持跨设备访问。样机 v2.1 纯 HTML5/CSS3/原生 JS 实现，零框架依赖，便于快速迭代验证 |
| **交互方式** | 鼠标/键盘为主 + 触摸（移动端） | 专业人员需要高效操作（快捷键 Ctrl+1/2/3、滑块键盘左右箭头）；移动端支持触摸拖拽和全屏卡片展开 |
| **前端框架** | 样机：纯 HTML/CSS/JS；生产：React 18 + TypeScript + Ant Design 5.x | 样机阶段框架无关以加速设计验证；生产阶段复用 Ant Design 基础组件 + 自建差异化组件（物理滑块/评分条/AI 代偿面板） |
| **PDF 渲染** | 内置阅读器（基于 PDF.js） | 支持 Bounding Box 高亮和坐标跳转 |
| **报告导出** | PPT/PDF（MVP）、Word（V1） | 覆盖高管汇报和顾问交付场景 |
| **企业集成** | 手动导入（MVP）、API 对接（V1） | MVP 快速验证，V1 深化集成 |
| **部署方式** | 本地部署/私有云优先 | 满足数据境内存储和合规要求 |

**技术约束对 UX 的影响：**

| 约束 | UX 应对策略 |
|------|-----------|
| 检索延迟 P95 <800ms | 骨架屏 + 进度反馈，减少感知等待 |
| 并发 Agent 会话 10 (MVP) | 排队指示 + 预计等待时间 + 后台处理通知 |
| Bounding Box 单页 (MVP) | 明确标注"单页溯源"，V1 扩展到多页 |

### Effortless Interactions

**必须 effortless 的交互：**

1. **数据上传与解析**
   - 拖拽上传 17 种格式
   - 自动解析并结构化提取
   - 进度可视化（后台处理，可继续其他工作）

2. **高保真溯源**（信任基础设施）
   - 点击结论 → 弹出溯源卡片
   - 点击"跳转" → 自动定位 PDF 坐标点
   - 置信度一目了然（高/中/低）

3. **方向验证**（SP 置信度）
   - 战略控制点卡片 → 展开"市场洞察"证据面板
   - 多 Agent 辩论时间线（谁支持/谁反对/为什么）
   - "为什么没选"——被否决替代方案可展开

4. **解码追溯**（BP 置信度）
   - 点击 BP 举措 → 追溯上游 SP 战略控制点
   - 三层解码透视图（公司→部门→岗位 KPI 逐级展开）
   - 每个 KPI 显示锚点（"来自 CSF-3：提升客户粘性"）

5. **执行校验**（EM 置信度）
   - 每个计划旁显示资源约束状态（绿灯/黄灯/红灯）
   - 里程碑合理性自动校验（"里程碑2与里程碑1间隔 8 周，行业基准 4-6 周 ⚠️"）
   - 偏差预警阈值可视化（谁设的、为什么、当前值）

6. **财务量化查看**
   - 每个战略建议旁显示 NPV/IRR
   - 点击展开敏感性分析（龙卷风图）
   - 情景对比滑块（拖动看变化）

7. **多 Agent 辩论查看**
   - 时间线视图展示辩论过程
   - 风险热力图（红/黄/绿）
   - 一键展开详细论据

8. **Checkpoint 审批**
   - 异步审批（高管随时随地）
   - 关键信息摘要（1 屏内）
   - 一键批准/修正/拒绝

**当前用户痛点（竞品不足）：**

| 痛点 | 竞品表现 | sisys 解决方案 |
|------|---------|--------------|
| 战略方向存疑 | 高管凭经验判断，无系统证据链 | 市场洞察证据面板 + 辩论可视化 + 替代方案对比 |
| SP→BP 解码失真 | SA 手动对齐，遗漏/曲解普遍 | 自动映射 + 逐条追溯 + 三层解码透视图 |
| 执行计划不可信 | 资源约束不透明，里程碑靠拍脑袋 | 资源仪表盘 + 里程碑校验 + 历史对比基准 |
| 数据溯源 | 人工查找 1-2 小时 | 30 秒自动跳转 |
| 高管审批 | 集中开会 2-3 周 | 异步审批 3-5 天 |
| 报告格式 | 手动调整 1 天 | 一键生成 1 小时 |
| 项目筛选 | 人工 200 小时/100 项目 | 自动 2 小时/100 项目 |

### Critical Success Moments

**决定成败的关键时刻：**

| 时刻 | 用户 | 成功标准 | 失败后果 | 信任节点 |
|------|------|---------|---------|---------|
| **第一次方向验证** | CEO 张总 | 展开市场洞察面板 + 理解辩论过程 + 认可方向 | 认为"AI胡说八道"，不再信任系统 | SP 置信度 |
| **第一次解码追溯** | 李经理 | 从 BP 举措追溯至 SP 控制点 | 认为"解码是黑箱"，不敢用 BP 输出 | BP 置信度 |
| **第一次执行校验** | CFO 王总 | 看到资源约束状态 + 里程碑合理性 | 认为"计划不切实际"，无法向董事会汇报 | EM 置信度 |
| **第一次溯源** | 李经理 | 30 秒内跳转到原始文档 | 失去信任，不再使用 | 信任基础设施 |
| **第一次高管审批** | CEO 张总 | 30 秒内理解态势并决策 | 认为系统太复杂，放弃使用 | SP 置信度+EM 置信度 |
| **第一次白标报告** | 王经理（顾问） | 品牌元素 100% 准确 | 无法交付客户，失去付费动力 | 全链条信任 |

**首次用户成功路径（Onboarding）：**

```
Day 1: 上传文档 → 自动解析 → 运行第一个分析工具 → 看到洞察
Day 2: 验证溯源 → 查看财务量化 → 生成第一份报告
Day 3: 邀请高管审批 → 获得反馈 → 完成第一个 Checkpoint
```

### Experience Principles

**指导 UX 设计的核心原则：**

| 原则 | 描述 | 设计含义（v2.1 样机实现） |
|------|------|---------|
| **30 秒原则** | 决策舱总览仪表盘必须在 30 秒内传递全局态势 | KPI 仪表盘 10 项指标（RAG 三色）+ 风险雷达 TOP3 + BG 健康矩阵 + 财务摘要条；折叠卡片显示最弱维度风险提示文字 |
| **SP 置信度** | 每个战略结论必须展示推导过程 + 实时 AI 代偿方案 | 三重置信度评分条（SP 方向分）+ 物理滑块推演 + AI 策略卡片（预览/采纳/撤销）；趋势历史≥50 点可点击放大 |
| **BP 置信度** | 每个 BP 举措必须可追溯至 SP 的战略控制点 | SP→BP 解码追溯带（Decode Ribbon）：CSF→KPI→目标值→权重完整链路，双向一键跳转卡片 |
| **EM 置信度** | 每个计划必须通过执行可行性验证 | BP 卡片展开态含供应链成本/上市周期/国产替代率滑块 + AI 代偿；工作台推演沙盘含情景切换（乐观/保守/自定义/决策） |
| **溯源即信任** | 工作台证据树：每个数据可追溯至原始来源 | 45+ 条证据覆盖 15 工序，新鲜度标签（🟢新鲜/🟡可用/🔴过期），权重折扣（fresh=1.0/stale=0.75），勾选即聚合参数 |
| **物理仿真交互** | 滑块操作必须有触觉级的即时反馈 | 惯性动量（松手继续滑，decay=0.94）+ notch 吸附（AI 推荐位蓝色圆点）+ 涟漪反馈（径向扩散 0.6s）+ 弹簧回弹（cubic-bezier 弹性曲线） |
| **评分即叙事** | 评分变化必须讲一个故事 | 四阶段动画交响乐：阶段 1 流光扫过（shimmer 0.3s）→ 阶段 2 光晕/震动（glow/shake）→ 阶段 3 数字平滑计数（分段加减速 1.2s）→ 阶段 4 持续微呼吸（6s 周期） |
| **品牌即价值** | 顾问报告必须 100% 符合品牌规范 | 可视化品牌编辑器、一键应用模板、导出时间<1 分钟 |
| **流程透明** | 用户随时知道进度和下一步 | 工作台七步层次树（15 工序三级嵌套）+ 决策卡片按严重度自动排序 + 全部处理完毕自动加载下一批 |
| **合规内建** | 审计追踪不打扰但完整 | 每页底部合规水印（WORM 保护 + 保留日期 + 审计 ID）+ 决策操作自动沉淀为决策证据 |
| **AI 透明性** | AI 代偿必须解释"为什么" | 三段式风险叙述：你调整了什么 → 这意味着什么 → 安全边际还有多少；每条 AI 策略含逻辑说明 + 分维度预测影响量化 |

### Shared Data Architecture — PARAM_REGISTRY

**决策舱与工作台共享的参数注册表（26 参数 × 6 tier）：**

`PARAM_REGISTRY` 是样机 v2.1 的核心数据架构，定义了推演沙盘和证据聚合引擎统一使用的参数体系。每个参数包含 `name`（中文名）、`unit`（单位）、`tier`（分类）、`default`（默认值）四个属性。

| Tier | 数量 | 代表参数 | UX 用途 |
|------|------|---------|--------|
| **环境** | 4 | mkt_growth（市场增速%）、localization（国产替代率%）、policy_support（政策支持度）、comp_lead（竞品提前月数） | 决策舱滑块 + 工作台外部环境参数面板 |
| **战略** | 3 | mkt_share（目标市场份额%）、channel_cov（渠道覆盖率%）、patent_count（专利数） | SP 方向评分计算输入 |
| **解码** | 3 | sp_bp_alignment（SP-BP 映射完整度%）、initiative_coverage（举措覆盖完整度%）、metric_coverage（指标覆盖率%） | BP 解码评分计算输入 + 解码追溯带权重标注 |
| **执行** | 10 | rd_budget（研发预算¥亿）、hc_gap（人才缺口人）、salary_comp（薪资竞争力%）、talent_pool（人才市场热度分）、supply_cost（供应链成本¥亿）、launch_cycle（上市周期月）等 | 决策卡滑块主体 + AI 代偿策略触发条件 + 工作台推演沙盘动态参数面板 |
| **监控** | 2 | milestone_achieve（里程碑达成率%）、talent_retention（关键人才留存率%） | EM 执行评分的实时监控输入 |
| **风险** | 4 | payback_years（投资回收期年）、cashflow_risk（现金流压力等级）、compliance（合规风险等级）、risk_mitigation_cov（风险缓解覆盖率%） | 风险雷达面板 + AI 代偿现金流/合规策略触发 |

**设计含义：**
- 决策舱滑块通过 `paramKey` 映射到 PARAM_REGISTRY 条目，滑块标签/单位/默认值自动从注册表解析
- 工作台证据聚合引擎通过 PARAM_REGISTRY 识别每条证据的 `params` 字段，按新鲜度权重×置信度加权平均计算参数值
- 26 个参数覆盖了从 SP 环境分析到 EM 执行监控的全链路，保证决策舱与工作台的数据一致性
- 新增参数只需在 PARAM_REGISTRY 注册即可自动出现在工作台动态参数面板（按 tier 分组）

### Emotional Design Principles

**情感化设计原则：**

| 原则 | 描述 | 应用示例 |
|------|------|---------|
| **先情感后功能** | 用户先感受，后思考 | 仪表盘先用颜色传达战略管理态势，再用数字传达细节 |
| **信任来自验证** | 信任不能"给予"，只能让用户"验证后获得" | 每个结论可点击展开证据链；替代方案可见；解码锚点可追溯 |
| **峰值时刻设计** | 创造让用户记住的瞬间 | 第一次方向验证：市场洞察面板完整展开——"原来如此！" |
| **透明建立信任** | AI 行为可见可理解 | 显示 Agent 辩论全部记录、工具使用、置信度、推理链 |
| **渐进式披露** | 避免信息过载 | 第一屏战略管理概览，点击任意节点展开证据 |
| **友好错误处理** | 错误时保持用户信心 | "SP→BP 解码偏差 8%，建议手动调整 3 项举措"而非"解码失败" |
| **庆祝小胜利** | 强化成就感 | 解码追溯全部高亮对勾、Checkpoint 完成时的进度庆祝动画 |
| **预警平衡设计** | 警觉性 + 可控感 | 预警显示等级 + 影响 + 建议措施 + 调整阈值入口 |

### Anti-Patterns to Avoid

**UX 反模式（避免）：**

| 反模式 | 问题 | 为什么避免 | 替代方案 |
|-------|------|-----------|---------|
| **信息过载仪表盘** | 第一屏显示 20+ 指标 | 高管无法 30 秒理解，失去掌控感 | 第一屏只显示 3 个关键指标 |
| **跳转新页面溯源** | 点击溯源打开新标签页 | 上下文切换，失去专注感 | 悬浮弹窗，保持当前上下文 |
| **仅显示数字无含义** | 只显示"NPV ¥12 亿" | CFO 不知道是否好，失去自信 | 显示"NPV ¥12 亿（高于资本成本 15%）✅" |
| **只报警无建议** | 预警只显示"风险高" | 增加焦虑，不增加可控感 | 预警 + 等级 + 影响 + 建议措施 |
| **魔法般 AI 结果** | 只显示结果不显示过程 | 技术用户不信任，怀疑可靠性 | 显示 Agent 思考过程 + 工具使用 |
| **模糊错误提示** | "Error 500"或"解析失败" | 用户不知道如何修复，挫败感 | "数据解析失败，请检查是否为 PDF/Excel 格式" |
| **无限加载无反馈** | 转圈 loading 无进度 | 用户焦虑，不知道要等多久 | 进度条 + 预计完成时间 |
| **强制同步等待** | 必须等待处理完成 | 效率低，用户无法做别的 | 后台处理 + 完成通知 |

## Design System Foundation

### 1.1 Design System Choice

**设计系统选择：Ant Design 5.x（生产）+ 纯 HTML/CSS/JS（样机）**

经过多方视角评审（架构/开发/UX/产品/业务），我们选择 **Ant Design 5.x + CSS-in-JS + Design Tokens** 作为 sisys 的生产设计系统基础。

**样机策略（v2.1）：** UX 样机 (`ux-design-prototype-v2.1.html`) 采用零框架依赖的纯 HTML5/CSS3/原生 JS 实现，所有 Design Tokens 通过 CSS 自定义属性 (`:root` 变量) 管理。此策略的优势：
- 无需构建工具，浏览器直接打开即可评审
- CSS 变量直接映射到生产环境的 Design Tokens，迁移零成本
- 自定义组件（SliderPhysics/ScoreBar/AICompensation）的交互逻辑可直接翻译为 React 组件

## Defining Experience

### 核心定义性体验：SP↔BP 信任闭环

经过多方视角评审（高管/战略规划人员/分析师/顾问/投资经理/UX/产品），并借鉴华为 DSTE（开发战略到执行）20 年验证的战略管理方法论，sisys 的核心定义性体验是 **SP 把控方向与节奏，BP 落实推进业务执行**。

这不是一条进度条能承载的——它需要在三个关键节点上，用 UX 让用户建立信念：**SP 置信度、BP 置信度、EM 置信度**。

---

### 信任层 1：SP 置信度（Direction Trust）

**"AI 定的这个方向真的对吗？凭什么？"**

战略方向是企业最重要的决策之一。让用户相信 AI 推荐的方向优于其他选项，需要回答三个子问题：

- 这个结论**基于什么数据和分析**？
- AI 考虑过**哪些替代方案**？为什么否决了它们？
- 不同角色（各 Agent）**是否有分歧**？最终为什么达成共识？

### Chosen Direction

**推荐设计方向组合：**

```
核心设计方向 = 方向 7（SP↔BP 信任闭环）+ 方向 1（高管优先）+ 方向 3（溯源信任）+ 方向 4（品牌灵活）

理由：
1. SP↔BP 信任闭环 - 产品不可替代的独特价值，所有用户类型的核心需求
2. 高管优先 - 服务付费决策者（CEO/CFO），确保 30 秒信任态势理解
3. 溯源信任 - 信任基础设施，服务三层信任构建
4. 品牌灵活 - 服务顾问，支持白标输出，付费动力
```

### Design Rationale

**设计决策理由：**

#### 为什么选择"SP↔BP 信任闭环"作为核心定义性方向？

| 理由 | 说明 |
|------|------|
| **不可替代的独特价值** | PRD 明确定位：SP 把控方向与节奏，BP 落实推进业务执行——这是竞品无法复制的系统能力 |
| **华为 DSTE 验证** | 20 年战略管理方法论支撑，"方向→解码→执行"闭环已被全球 20 万人规模企业验证 |
| **信任是决策前置条件** | 高管不信任方向，不会批准 SP；专业人员不信任解码，不敢执行 BP；CFO 不相信能落地，不会批预算 |
| **差异化极致** | 竞品提供工具（Tableau/Palantir），sisys 提供信任——从"分析工具"跃迁为"决策基石" |

#### 为什么保留"高管优先"作为并行主导方向？

| 理由 | 说明 |
|------|------|
| **付费决策者** | 高管（CEO/CFO）是付费决策者，他们的体验决定购买 |
| **与方向 7 天然互补** | 高管优先解决"效率"（30 秒），方向 7 解决"信心"（为什么信） |
| **口碑传播** | "这个系统让我 30 秒内看清战略管理态势，5 分钟做出决策！" |

#### 为什么"溯源信任"重新定位为基础设施？

| 理由 | 说明 |
|------|------|
| **服务面不变** | 全员使用、高频、差异化——仍然是必须完美的底层体验 |
| **角色变化** | 从"核心定义性体验"降维为"三层信任的数据基础"——溯源本身不是目的，建立信任才是 |
| **与方向 7 的关系** | 方向 7 的每一层信任节点都依赖溯源能力——市场洞察面板上的每个数据点、SP→BP 映射的每个锚点、资源约束的每个校验基准，都需要溯源支撑 |
