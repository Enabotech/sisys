## Executive Summary

### 愿景对齐

**sisys** 是面向**大中型企业高管团队**、**企业战略与市场体系人员**和**专业顾问**的 AI 驱动战略规划与决策智能平台。系统通过多 Agent 协作（CEO/CFO/CMO/CTO/CFO/CHO/AUD 七种专业角色）和内置合规审计（7 年 WORM 存储），解决企业战略规划中的三大核心痛点：

1. **高管团队协调难** - 战略规划需要多角色视角，但高管时间难以协调，决策质量依赖个人经验
2. **数据分散决策难** - 决策质量依赖数据，但企业数据分散在不同系统，难以形成完整洞察
3. **流程长效率低** - 大中型企业战略规划参与人员多、流程长、效率低，从数周到数月不等

**核心价值主张：**

| 用户群体 | 核心价值 |
|---------|---------|
| **高管用户** (CEO/CFO/CTO 等) | 通过 AI 协作在几天内达成战略共识，而非数周会议；决策质量提升 40% |
| **企业战略与市场体系人员** | 标准化战略分析流程，快速获取专业洞察，减少重复性数据整理工作，专注于高价值分析 |
| **顾问用户** | 3 小时完成原本需要 1 天的分析报告，效率提升 3 倍，输出质量标准化 |
| **企业用户** | 战略规划周期缩短 50%，确保战略落地执行，7 年审计追踪满足合规要求 |

**未来状态：** 战略不是高高在上的空中楼阁，而是快速智能响应业务动态的"军中诸葛亮"。

---

### What Makes This Special

**碾压性优势：**

| 能力 | 用户价值 |
|------|---------|
| 输入企业数据 → 最优战略规划 | 精准高效制定 SP/BP，避免人为偏差 |
| 输入专业数据 → 高质量洞察报告 | 生成专业级商业洞察，支持客户交付 |
| 快速响应市场动态 | 实时提供高质量商业决策支持 |
| 全流程闭环管理 | 客观差距分析→精准市场洞察→合理战略目标→高价值战略创新→最优业务设计→完美执行设计→高保真战略解码→高效战略闭环 |

**核心差异化：**

1. **多 Agent 协作** - 模拟高管团队的多视角辩论，通过红蓝对抗机制输出风险全景视图
2. **数据驱动决策** - RAG+ 知识图谱确保决策基于事实，支持高保真视觉级溯源（Bounding Box 跳转至原始文档坐标点）
3. **全流程闭环** - 从 SP 到 BP 到执行设计的完整链路，内置 BLM/BEM 模型不变性保证
4. **合规内建** - 7 年 WORM 存储、审计追踪、数据主权隔离，满足 SOX/ISO27001 合规要求
5. **三视图设计** - 高管视图 (简化决策)、分析师视图 (专业工具)、企业战略与市场人员视图 (流程标准化)

**核心洞察：**
- 战略规划的本质是**多视角共识构建**，而非单点分析优化
- 决策质量的瓶颈是**数据可及性**，而非分析能力
- 战略执行的关键是**闭环追踪**，而非规划文档本身

**创新背景：**

**预期效果：**

|---------|---------|---------|---------|
| **企业租户** | Schema 级隔离 | PostgreSQL Schema per Tenant | 大型企业、中型企业 |
| **顾问租户** | 行级隔离 | Row-Level Security + TenantID | 小型咨询公司、个人顾问 |
| **项目级隔离** | 对象存储隔离 | MinIO Bucket per Project | 所有客户 |

**技术实现要点：**

| 组件 | 技术选择 | 隔离机制 |
|------|---------|---------|
| **数据库** | PostgreSQL 15+ | Schema 隔离 + RLS (Row-Level Security) |
| **向量库** | Qdrant 1.7+ | Collection per Tenant |
| **缓存** | Redis 7.0+ | Key 前缀隔离 (tenant:{id}:...) |
| **对象存储** | MinIO | Bucket per Project + 策略隔离 |
| **消息队列** | RabbitMQ | VHost per Tenant |

### 2. 智能检索与知识发现（SR - Search & Retrieval）[or.md 二.3-二.7]

#### P0 功能（MVP 必需）

- **SR-01 (P0):** 系统可以执行混合检索（Dense bge-m3 + BM25 稀疏检索），双路召回 [or.md 二.3.(1)]
- **SR-02 (P0):** 系统可以抽取实体（LLM+ 规则混合策略），输出三元组 [or.md 二.3.(2)]
- **SR-03 (P0):** 系统可以管理战略领域词典库，支持热更新与版本管理 [or.md 二.3.(3)]
- **SR-04 (P0):** 系统可以对齐与消歧实体（基于编辑距离 + 语义相似度双路匹配）[or.md 二.3.(4)]
- **SR-05 (P0):** 系统可以融合三路检索结果（Dense + Sparse + Graph/metadata signals），使用 RRF 融合排序 [or.md 二.3.(6)]
- **SR-06 (P0):** 系统可以执行分层检索（L1 跨文档摘要→L2 文档摘要→L3 文档切片→L4 实体级片段）[or.md 二.4.(1)]
- **SR-07 (P0):** 系统可以根据查询复杂度与意图自动路由至对应检索层级 [or.md 二.4.(2)]
- **SR-08 (P0):** 系统可以生成契约化结构化摘要（财务/市场/技术视角），输出符合预定义 JSON Schema [or.md 二.5.(1)]
- **SR-09 (P0):** 系统可以评估摘要质量（信息熵 + 关键实体覆盖率），评分<0.7 自动触发二次生成 [or.md 二.5.(2)]
- **SR-10 (P0):** 系统可以评估检索相关性（LLM-as-a-Judge 实时多维评估），相关性<0.6 标注"数据不足" [or.md 二.6.(1)]
- **SR-11 (P0):** 系统可以触发自动补救机制（扩展检索范围/调用白名单外部数据源/生成数据缺口报告）[or.md 二.6.(3)]
- **SR-12 (P0):** 系统可以保留引文"三元组"特征（文档 ID、切片 ID、字符范围），支持 Bounding Box 级溯源 [or.md 二.7.(1)]

### 概述

**非功能需求（NFR）定义：**
NFR 定义系统**表现得多好**，而不是它**必须做什么**。它们指定质量属性，如性能、安全性、可扩展性等。

**选择性方法：**
我们只记录对 **sisys** 重要的 NFR。如果某个类别不适用，我们完全跳过它。

**NFR 与 FR 的关系：**
- **FR（功能需求）** 定义 WHAT（系统必须做什么）
- **NFR（非功能需求）** 定义 HOW WELL（系统必须做得多好）
- **算法细节**（如 RRF 参数、UDMR 评分公式）在 NFR 中定义，FR 引用

**NFR 优先级：**
- **P0（MVP 必需）** - 性能/安全性/合规性/可靠性，MVP 必须通过验收测试
- **P1（V1 增加）** - 可扩展性/集成性/可访问性，V1 必须满足
