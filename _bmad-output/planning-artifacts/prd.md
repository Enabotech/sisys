## 1. 执行摘要

### 1.1 产品概述

企业战略规划管理智库系统是一款基于先进 Agent 技术的企业级智能决策支持平台。系统通过多 Agent 协作机制，将复杂的战略规划过程（五年滚动战略规划 SP 和年度业务计划 BP）转化为可执行、可追溯、可优化的认知流水线。

### 1.2 核心价值主张

| 价值维度 | 说明 |
|----------|------|
| **生产力跃升** | 将传统数周的战略规划周期压缩至数小时，同时保持人类监督的弹性 |
| **决策质量提升** | 基于 GraphRAG 知识图谱和多 Agent 辩论机制，减少认知偏见和决策盲区 |
| **知识资产沉淀** | 将企业历年战略规划、执行数据、决策依据转化为可复用的战略档案库 |
| **合规可解释** | 全链路审计日志、引文溯源、决策依据透明化，满足 SOX/ISO27001 合规要求 |

### 1.3 关键差异化因素

1. **方法论驱动** - 严格遵循 BLM（业务领先模型）和 BEM（业务执行模型）战略管理方法论
2. **双核引擎架构** - Prefect（数据管道）+ LangGraph（Agent 编排）混合执行模型
3. **零信任安全** - 五层纵深防御体系（隔离→执行→检测→审计→熔断）
4. **开放生态** - 基于 MCP/A2A 协议的工具箱微服务架构，支持第三方工具集成

### 1.4 商业目标

| 目标类别 | 具体目标 | 衡量指标 |
|----------|----------|----------|
| **市场目标** | 成为企业级战略规划 AI 首选平台 | 12 个月内获取 50+ 企业客户 |
| **技术目标** | 建立 Agent 协作战略规划的行业标准 | 发布开源工具箱协议标准 |
| **财务目标** | 实现可持续的 SaaS 收入模型 | ARR（年度经常性收入）$5M+ |

## 2. 产品愿景

### 2.1 愿景陈述

**让每一家企业都拥有宗师级战略规划能力。**

通过 AI Agent 协作系统，将顶尖咨询公司（如麦肯锡、波士顿咨询）的战略规划方法论和能力 democratize，使中小企业也能以可负担的成本获得高质量、可执行、可追溯的战略规划服务。

### 2.2 产品原则

| 原则 | 说明 | 设计影响 |
|------|------|----------|
| **人类监督** | AI 是增强而非替代人类决策 | 所有关键决策点设置 Checkpoint 人工介入 |
| **方法论不变性** | 严格遵循 BLM/BEM 模型逻辑步骤 | 演进过程不得改变战略模型定义的核心流程 |
| **证据驱动** | 所有结论必须有可追溯的证据支撑 | 强制引文溯源、证据包打包、交互式溯源树 |
| **成本透明** | 用户清楚知道每次任务的 AI 成本 | 实时成本监控、三级熔断机制、预算预测 |
| **隐私优先** | 敏感数据本地处理，外部调用需审计 | 混合部署架构、数据主权隔离、字段级加密 |

### 2.3 成功指标

### 3.2 核心人物画像

#### 人物画像 1：张总 - 中型科技企业 CEO

**基本信息：**
- 年龄：45 岁
- 职位：CEO，某智能硬件科技公司（员工 300 人，年营收 5 亿）
- 背景：技术出身，MBA 学位，首次创业成功

**目标与动机：**
- 制定清晰的 5 年战略规划，明确公司发展方向
- 在有限时间内（董事会要求 2 周内完成）产出高质量 SP
- 确保战略规划可执行、可落地，而非纸上谈兵

**痛点与挑战：**
- 缺乏专业战略规划团队，依赖外部咨询公司（成本高、周期长）
- 市场变化快，传统年度规划无法适应快速变化
- 难以平衡短期业绩压力和长期战略投入

**使用场景：**
- 通过 CLI 或 Web 界面启动 SP 规划任务
- 在关键 Checkpoint 介入评审和决策
- 查看多方案对比（保守/激进/AI 融合），做出最终选择
- 接收战略偏差预警，及时调整执行策略

**对系统的期望：**
> "我希望系统能像一个经验丰富的战略顾问团队，给我提供专业、可执行的建议，但最终决策权在我手中。"

```
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                      基础设施层 (Infrastructure)                 │
│  Prefect (数据管道)  │  LangGraph (Agent 编排)  │  RabbitMQ (事件) │
│  PostgreSQL │ Qdrant (向量) │ Neo4j (图谱) │ MinIO (对象)        │
└─────────────────────────────────────────────────────────────────┘
```

**系统核心抽象（设计基础）：**

本系统基于两个核心抽象构建，这是整个系统设计的理论基础：

| 核心抽象 | 定义 | 技术实现 |
|---------|------|----------|
| **系统公理一：自主调用** | trigger(事件)→route(AGENT/工具)→execute(session) 的自主调用循环 | 事件总线 + 会话路由 + 状态持久化 |
| **系统公理二：外部化记忆** | LLM 上下文=缓存、磁盘记忆=真相源的记忆分离原则 | 四层记忆架构 + 战略档案库 + 检索 - 压缩循环 |

**系统公理一：自主调用循环详细机制：**

```
trigger(事件) → route(路由) → execute(执行)
     ↓              ↓             ↓
外部事件/心跳   session_id 哈希   会话命名空间
周期性心跳事件   路由至 AGENT/工具  状态持久化与中断恢复
```

- **Trigger（触发器）**：
  - 外部事件：用户命令、API 请求、文件上传
  - 周期性心跳事件：每日自动唤醒检查待办事项、偏差预警
  - 事件格式标准化：事件 ID、类型、时间戳、载荷、来源、Schema 版本

- **Route（路由）**：
  - 基于 session_id 哈希路由至 AGENT 或工具
  - 会话绑定：同一 session_id 的所有操作共享上下文
  - 负载均衡：根据 AGENT 实例池负载动态路由

- **Execute（执行）**：
  - 在会话命名空间中执行，支持状态持久化与中断恢复
  - 状态快照序列化至高速缓存存储（Redis）
  - 高速缓存配置：支持主从复制与故障转移，TTL 可配置 24 小时至 30 天
  - Time-travel 能力：支持从任意历史快照恢复执行

**系统公理二：外部化记忆详细机制：**

```
┌─────────────────────────────────────────────────────────────┐
│                    记忆分离架构                              │
├─────────────────────────────────────────────────────────────┤
│ LLM 上下文（缓存）                                           │
│ - 仅保留当前任务必需的压缩信息                               │
│ - 防止上下文爆炸                                             │
│ - 工作记忆（24h）+ 短期记忆（30 天）                           │
├─────────────────────────────────────────────────────────────┤
│ 磁盘记忆（真相源）                                           │
│ - 会话状态与推理轨迹持久化存储                               │
│ - 战略档案库（永久存储）                                     │
│ - 长期记忆（向量 + 对象 + 图谱存储）+ 程序记忆                 │
└─────────────────────────────────────────────────────────────┘
```

- **检索 - 压缩循环机制**：
  - 压缩前必须执行持久化笔记步骤，防止信息丢失
  - 上下文压缩器：基于关键实体抽取与 HyDE 算法
  - 压缩率目标：≥70%
  - 持久化笔记：关键结论、决策依据、引用源写入战略档案库

- **战略档案库（长期记忆存储）**：
  - 分层存储架构：
    - 高速缓存层：处理会话状态与语义缓存（Redis）
    - 关系存储层：处理用户权限与审计元数据（PostgreSQL）
    - 向量存储层：处理嵌入向量与相似度检索（Qdrant）
    - 对象存储层：处理原始文档与版本快照（MinIO）
    - 图存储层：处理知识图谱与实体关系（Neo4j）
  - 事实有效期标签管理（valid_from/valid_until）
  - 超 12 个月数据自动标记"数据陈旧"并降权

**OCR 与主动学习优化：**
- 支持中/英双语 OCR 解析
- 置信度<0.85 时自动标注"待人工复核"

- 阈值自适应调整：基于文档类型动态调整置信度阈值（范围 0.7-0.9）

**输出：**
- 结构化 JSON 数据（包含元数据、切片、嵌入向量）
- 知识图谱三元组（实体 - 关系 - 实体）
- 索引引用（用于后续检索）

**性能指标：**
- OCR 置信度：≥0.85（支持自适应调整，范围 0.7-0.9）
- 实体抽取准确率：≥80%
- 索引构建延迟：P95<200ms
- 数学公式支持：LaTeX 与 MathML 双格式表达

#### 5.2.2 混合检索引擎（GraphRAG）

**功能描述：** 支持语义 + 关键词 + 图谱的三路融合检索

**检索架构：**
```
L1: 跨文档摘要层（主题级检索）
     │
L2: 文档摘要层（文档级检索）
     │
L3: 文档切片层（片段级检索）
     │
L4: 实体级片段层（实体级检索）
```

**检索策略：**
- **简单查询** → Vector RAG（低延迟）
- **复杂推理** → GraphRAG（高准确率）
- **自适应路由** → 基于查询复杂度自动选择

**融合排序：**
- Dense（bge-m3）+ Sparse（BM25）+ Graph/metadata
- 可配置权重的 RRF 融合
- ColBERT-v2 重排序（Top-100→Top-20）

**战略领域词典库：**
- 覆盖核心战略概念目标≥95%（如 BLM、BEM、PESTEL、波特五力等）
- 支持词典热更新与版本管理，新词入库自动触发增量图谱构建
- 支持动态扩展与热度淘汰，基于使用频率自动调整词条权重
- 领域词典 AC 自动机匹配，保障实体抽取高准确率（目标≥80%）

**智能语义分块：**
- 由文档语义边界而非固定字数进行切片
- 平均片段长度目标≈300 tokens（允许配置，范围 200-500 tokens）
- 保持上下文完整性，避免切断关键信息

**性能指标：**
- precision@k: >0.8
- recall@k: >0.8
- 检索延迟 P95: <200ms（分级精排 Top-100→Top-20）

#### 5.2.4 多 Agent 协作引擎

**功能描述：** 7 个角色 Agent 基于状态图的协作编排

**Agent 角色：****
| Agent | 职责 | 视角 |
|-------|------|------|
| **CEO** | 战略方向、最终决策 | 全局视角 |
| **CFO** | 财务验证、风险评估 | 财务视角 |
| **CMO** | 市场分析、客户洞察 | 市场视角 |
| **CTO** | 技术可行性、创新焦点 | 技术视角 |
| **CHO** | 组织能力、人才策略 | 人力视角 |
| **COO** | 运营执行、关键任务 | 运营视角 |
| **AUD** | 一致性检验、审计 | 独立审计视角 |
| **SYS** | 任务分发、仲裁 | 指挥官视角 |

**协作机制：**
- **分层架构**：SYS AGENT 分解 → 专业 Agent 并行 → 调度器协调
- **视角隔离**：Prompt 隔离、工具隔离、数据隔离
- **辩论机制**：发散（T=0.8）→ 收敛（T=0.5）→ 裁决（T=0.2）
- **Checkpoint**：关键节点暂停、用户介入、恢复执行

**状态管理：**
```python
class AgentState(TypedDict):
    session_id: str
    current_phase: str  # BLM/BEM 阶段
    agent_role: str
    working_memory: list
    long_term_memory_ref: str
    tools_used: list
    confidence_score: float
    cost_accumulated: float
```

**AGENT 标准工作流（9 步）：**

基于状态图的工作流引擎，采用 StateGraph 机制定义显式状态模型：

| 步骤 | 名称 | 详细说明 |
|------|------|----------|
| **1. 初始化** | 加载环境配置 | 加载环境配置并初始化，根据用户偏好（风险偏好、时间压力、任务上下文）渲染价值观模板，实例化会话级沙箱与混合检索记忆容器 |
| **2. 感知** | 读取数据生成摘要 | 读取经处理的结构化 JSON 数据，自动生成全景数据摘要（含关键指标趋势、异常波动、关联文档清单），生成并加载任务上下文 |
| **3. 规划** | 生成任务执行 DAG | 生成任务执行 DAG，匹配工具映射，输出机器可读的任务编排 JSON（包含子任务列表、匹配工具映射、数据依赖边） |
| **4. 执行** | 原子循环调度 | 按拓扑顺序调度子任务，每个子任务内执行 `Think→Code→Execute→Observe→Validate` 原子循环；每次输出均经审计校验，通过则写入持久化沙箱内存变量，失败则重试或回退（最大 3 次） |
| **5. 深度思考** | 多路径推演（可选） | 在关键决策节点并行生成多条思维链推演路径，通过内部验证打分选出最优解 |
| **6. 验证** | 结构化检查输出 | 结构化检查输出是否符合 Schema 契约；支持置信度达标且目标达成时提前终止 |
| **7. 反思** | 错误分析与修正 | 增加反思阶段权重，错误分析驱动持续改进，捕获执行过程中的问题并修正策略 |
| **8. 证据打包** | 全量元数据归档 | 任务全部完成后，系统自动收集本次任务执行全量元数据、中间产物、最终输出，封装为证据包并写入战略档案库 |
| **9. 演化** | 轨迹存入数据集（可选） | 匿名化执行轨迹存入工具箱演进数据集，作为后续 Strat-Bench 扩增样本或任务拆解策略优化的输入源 |

**深度思考与多路径推演：**
- 在 SP/BP 所有核心分叉点（如商业模式选择、核心竞争力定义），默认调用支持深层推理的模型
- 并行生成多条思维链推演路径，通过内部验证打分选出最优解

**中断安全与状态持久化：**
- 任意节点支持用户中断
- 自动保存 StateSnapshot 序列化至高速缓存存储（支持主从复制与故障转移）
- 恢复时加载完整上下文与工具状态
- 支持从任意历史快照恢复执行（Time-travel 能力）
- 支持从任意 Checkpoint 恢复执行后修改中间状态变量并从修改点继续执行

**AGENT 实例池化与动态扩缩容：**
- 基于负载自动伸缩 AGENT 实例数量
- 并发量高时自动增加 AGENT 实例（触发阈值：队列等待>30 秒或 CPU>70%）
- 低负载时自动缩减 AGENT 实例（触发阈值：并发<5 且持续 10 分钟）
- 实例池预热：预先启动 3-5 个 AGENT 实例以应对突发请求
- 健康检查：每分钟检测 AGENT 实例健康状态，故障实例自动剔除并替换

#### 5.2.5 战略规划引擎（BLM/BEM）

**功能描述：** 基于 BLM 模型的 SP 和 BEM 模型的 BP 生成

**SP（BLM 模型）六阶段：**
1. **业绩差距分析** - 识别当前与目标的差距
2. **市场洞察** - 看趋势/看市场/看竞争/看自己/看机会
3. **战略意图与目标** - 明确战略方向和量化目标
4. **创新焦点** - 价值创新、模式创新
5. **业务设计** - 商业模式、竞争策略
6. **执行设计** - 关键任务、组织/人力/文化策略

**BP（BEM 模型）六阶段：**
1. **澄清战略方向与运营定义**
2. **导出中长期关键战略举措**
3. **导出战略衡量指标**
4. **确定年度业务关键措施并导出具体目标**
5. **分解关键措施和目标**
6. **导出重点工作计划**

**战略解码器：**
- SP_Output_Schema → BP_Input_Schema 结构化映射
- 确保战略 - 执行一致性

**决策质量评估器：**
- 基于贝叶斯网络计算决策置信度
- 输入变量：证据充分性、逻辑一致性、历史成功率、专家意见一致性
- 输出：决策置信度评分（0-1）
- 置信度<0.7 时触发额外审核流程
- 支持敏感性分析，识别对决策影响最大的关键变量

**输出格式：**
- JSON 思维链：`Input -> <Reflection>...</Reflection> <Tools_Used>...</Tools_Used> <Constraints_Check>...</Constraints_Check> -> JSON`
- PDF/Markdown 报告（含可点击引文索引）

#### 5.2.6 审计与一致性保障

**功能描述：** AUD AGENT 旁路监听、异步阻断、五维一致性检验

**审计维度：**
| 维度 | 检验内容 | 异常阈值 |
|------|----------|----------|
| **事实一致性** | 对比原始文档切片 | 不可溯源标记异常 |
| **逻辑一致性** | 规则引擎检测内部矛盾 | 矛盾检测即标记 |
| **数值一致性** | 沙箱重计算关键指标 | 误差>5% 标记异常 |
| **时效一致性** | 引用数据超 12 个月 | 强制标记"数据陈旧" |
| **合规一致性** | 法规/政策符合性 | 违规即标记 |

**分级熔断：**
- **L1**（幻觉概率>0.8）：自动触发修正
- **L2**（0.6-0.8）：通知相关 AGENT 重试（最多 2 次）
- **L3**（<0.6）：暂停任务、生成 Hallucination Report、人工介入

**自动补救机制：**
当检索相关性低于阈值（默认 0.6）或被判定为"事实冲突"时，系统阻断直接生成以防幻觉，标注为"数据不足"，并触发以下自动补救流程：

| 步骤 | 补救策略 | 详细说明 |
|------|----------|----------|
| **1. 扩展检索范围** | 时间扩展 | 扩大时间范围（如从近 1 年扩展到近 3 年） |
| | 来源扩展 | 从单一来源扩展到多来源（内部文档→外部白名单数据源） |
| | 模态扩展 | 从文本扩展到表格、图表等多模态数据 |
| **2. 调用外部数据源** | 白名单 API | 调用预定义的外部财经数据 API（如 Bloomberg、Wind 等） |
| | 行业报告库 | 检索第三方行业报告数据库 |
| **3. 生成数据缺口报告** | 结构化报告 | 生成"数据缺口报告"，明确列出缺失的数据类型和来源 |
| | 用户补充提示 | 提示用户补充特定文档或数据 |
| **4. 记录补救成功率** | 策略配置 | 记录每种补救策略的成功率，用于优化后续补救决策 |
| | 效果评估 | 评估补救后检索相关性提升幅度，目标提升至≥0.6 |

**审计日志：**
- 不可变存储（WORM）
- 保留期限：7 年（SOX 合规）
- 支持按时间/角色/任务类型多维检索

#### 5.2.7 记忆与上下文管理

**功能描述：** 四层记忆架构、公共黑板机制、时间旅行调试

**记忆架构：**
| 层级 | 存储内容 | 有效期 | 存储引擎 |
|------|----------|--------|----------|
| **工作记忆** | 当前会话上下文 | 24h | Redis 缓存 |
| **短期记忆** | 最近项目数据 | 30 天 | PostgreSQL |
| **长期记忆** | 战略知识库 | 永久 | Qdrant+MinIO+Neo4j |
| **程序记忆** | 技能/工具使用模式 | 永久 | 版本管理存储 |

**公共黑板机制：**
- 基于 StateSnapshot + Redis MVCC
- 关键结论写入条件：重要性评分>3.5 + 置信度>0.7 + 引用源
- 支持多版本并发控制

**时间旅行调试：**
- 从任意 Checkpoint 恢复执行
- 状态快照增量归档至 MinIO
- 支持修改中间状态变量后继续执行

---

#### 5.2.8 成本优化引擎

**功能描述：** 动态模型路由、语义缓存、三级熔断

**动态模型路由：**
```
路由决策 = 语义匹配 (60%) + 历史成功率 (40%)

简单任务 → Ollama 本地模型（低成本）
复杂任务 → Claude/GPT-4（高性能）
```

**语义缓存：**
- 基于 bge-m3 相似度计算
- 相似度>0.9 直接命中缓存
- 目标降低 Token 消耗 40-50%

**三级熔断：**
| 级别 | 触发条件 | 响应 |
|------|----------|------|
| **任务级** | 单次 Token 超阈值（基础 5K/复杂 50K） | 立即终止 |
| **会话级** | 日累计 Token 超配额（默认 100 万） | 暂停新任务 |
| **系统级** | 连续 3 次失败或成本超预算 200% | 告警、管理员介入 |

#### 10.3.8 成本优化详细机制

**语义缓存：**
- **相似度计算**：bge-m3 嵌入向量相似度
- **命中阈值**：>0.9 直接返回缓存结果
- **失效策略**：
  - TTL 24 小时
  - 事件驱动失效（数据更新时失效）
  - 版本感知失效（模型版本变更时失效）
- **目标效果**：降低 Token 消耗 40-50%

**动态模型路由：**
```
路由评分 = 语义匹配（60%）+ 历史成功率（40%）

简单任务 → Ollama 本地模型（低成本）
复杂任务 → Claude/GPT-4（高性能）
```

**三级成本熔断：**
| 级别 | 触发条件 | 响应 |
|------|----------|------|
| **任务级** | 单次 Token 超阈值（基础 5K/复杂 50K） | 立即终止 |
| **会话级** | 日累计 Token 超配额（默认 100 万） | 暂停新任务，已启动任务完成 |
| **系统级** | 连续 3 次失败或成本超预算 200% | 告警，需管理员介入 |

**成本预���：**
- 基于历史相似任务预测 Token 消耗与 API 成本
- 偏差>50% 时提示用户确认
