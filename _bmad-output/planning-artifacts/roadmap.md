## 执行摘要

### 范围统一原则

本统一范围定义基于以下**系统整体视角**和**商业价值视角**原则：

#### 系统整体视角（System-Wide Perspective）

| 原则 | 描述 | 应用 |
|------|------|------|
| **架构一致性** | 功能模块必须与六边形架构一致，领域层零依赖 | 所有功能按领域边界划分优先级 |
| **能力分层** | 基础能力→核心能力→差异化能力→护城河能力 | MVP 聚焦基础 + 核心，V1 建立差异化 |
| **依赖管理** | 前置依赖必须优先实现（如 RAG→多 Agent） | 演进路线遵循技术依赖图 |
| **质量内建** | 合规/安全/性能不是附加功能，是基础能力 | MVP 必须包含基础审计/安全 |

#### 商业价值视角（Business Value Perspective）

| 原则 | 描述 | 应用 |
|------|------|------|
| **付费点优先** | 能直接产生收入的功能优先 | MVP 必须支持白标输出（顾问付费） |
| **高频驱动** | 高频用户（企业战略人员）需求优先 | MVP 优先服务专业人员，非高管 |
| **口碑传播** | 能产生"哇时刻"的功能优先 | MVP 必须包含高保真溯源 |
| **竞争壁垒** | 能建立护城河的功能优先 | V1 必须包含多 Agent 辩论 |

## 统一范围定义

### MVP - 最小可行产品（8 周）

**主题：单点突破，验证核心价值**

**目标用户：** 企业战略与市场体系人员（高频用户）+ 专业顾问（付费用户）

**商业目标：**
- 验证**高保真溯源**核心价值（30 秒溯源 vs 人工 2 小时）
- 验证**白标报告**付费意愿（顾问可直接交付客户）
- 获取 3 家付费试点客户，¥100 万 ARR

#### MVP 功能集合（P0 级 - 必须包含）

| 功能模块 | 功能描述 | 系统视角理由 | 商业视角理由 | 验收标准 |
|---------|---------|-------------|-------------|---------|
| **单 Agent 执行** | CEO Agent 完整工作流（Think→Code→Execute→Observe→Validate） | 验证自主调用公理 | 证明 AI 可独立完成任务 | 闭环成功率≥95% |
| **基础 RAG 检索** | Dense + Sparse 双路召回 + RRF 融合 | 记忆分离公理基础实现 | 检索是溯源前提 | 延迟 P95<800ms，相关性≥0.7 |
| **高保真溯源** | Bounding Box 坐标级跳转（单页）+ 置信度显示 | 系统公理二（外部化记忆）关键实现 | **核心差异化**，建立信任第一步 | 响应<300ms，定位准确率≥95% |
| **BLM 前两阶段** | 业绩差距分析 + 市场洞察（含流程可视化） | 验证编排服务协调双引擎 | 覆盖 80% 战略规划场景 | 流程标准化≥90% |
| **Checkpoint 机制** | 阶段完成快照 + 用户反馈 + 基础恢复 | 状态管理基础，支持中断恢复 | 用户体验关键（误操作恢复） | 恢复时间<30 秒 |
| **文档上传解析** | 17 种格式支持 + OCR + 结构化提取 | 数据接入层基础能力 | 用户第一个触点，决定留存 | 解析准确率≥95% |
| **基础多租户** | Schema per Tenant + RBAC 基础 | 六边形架构领域隔离要求 | 顾问多客户数据隔离必需 | 隔离测试 100% 通过 |
| **白标输出基础** | 品牌 Logo/配色/字体替换 + PPT/PDF 导出 | 报告生成流程验证 | **顾问付费点**，可直接交付 | 品牌元素 100% 准确，导出<1 分钟 |
| **基础审计日志** | 操作日志记录 + 查询 + 导出 | 合规内建原则 | SOX/ISO27001 基础要求 | 日志完整性 100% |
| **高管仪表盘（简化版）** | 3 个关键指标 + 红/黄/绿状态 + Checkpoint 审批 | 接口层基础能力 | **付费决策者**需要看到价值 | 30 秒理解率≥90% |

#### MVP 技术指标（P0 级 - 必须达标）

| 指标 | 目标值 | 衡量方式 | 商业意义 |
|------|-------|---------|---------|
| 检索延迟 P95 | <800ms | Prometheus 监控 | 用户体验底线 |
| 系统可用性 | 99% | Uptime 监控 | 企业关键决策系统 |
| 溯源成功率 | ≥95% | 日志分析 | 信任建立关键 |
| 审计追踪完整性 | 100% | 日志完整性检查 | 合规底线 |
| 文档解析准确率 | ≥95% | 抽样验证 | 第一印象 |
| 白标品牌准确率 | 100% | 客户验收 | 付费意愿 |

#### MVP 明确排除（P2 级 - 后续版本）

| 功能 | 排除原因 | 纳入版本 | 风险缓解 |
|------|---------|---------|---------|
| 完整多 Agent 协作（7 种角色） | 复杂度高，单 Agent 可验证核心价值 | V1 | MVP 用 CEO Agent 覆盖主要场景 |

| 完整合规审计（7 年 WORM） | 基础审计日志可满足 MVP 合规 | V2 | MVP 用 PostgreSQL 审计表 |
| 外部企业数据整合 | 需要数据源对接， MVP 用导入 | V1 | MVP 支持手动导入外部数据 |
| 压力测试建模 | 金融行业特定需求 | V2 | MVP 用基础敏感性分析 |
| 语义缓存 | 性能优化，非功能必需 | V1 | MVP 用基础缓存 |

| **商业价值优先** | 能直接产生收入的功能可提前 | 白标输出从 V1 提前至 MVP |
| **依赖不可跳跃** | 前置依赖必须先实现 | RAG 不完善前不做多 Agent |
| **质量内建** | 合规/安全不是附加功能 | MVP 必须包含基础审计 |
| **用户验证驱动** | 未验证功能不纳入下一版本 | MVP 未验证前不启动 V1 |

### 变更流程

```
1. 变更提出 → 2. 影响分析（系统/商业双视角） → 3. 优先级重评
       ↓
4. 范围调整 → 5. 路线图更新 → 6. 干系人沟通
```

## 使用指南

### 给产品团队

- 本范围定义是**唯一真相源**，所有 PRD/UX/架构文档的范围章节必须与此对齐
- 版本演进遵循**依赖关系图**，不可跳跃
- 优先级调整需经过**系统视角 + 商业视角**双维度评估

### 给开发团队

- MVP 聚焦**P0 级功能**，不主动实现 P1/P2 功能
- 架构设计需支持**平滑演进**（MVP→V1→V2→V3+）
- 技术指标是**验收底线**，不是目标

### 给 UX 团队

- MVP 优先设计**高保真溯源**和**白标报告**流程
- 高管仪表盘 MVP 是**简化版**，完整版在 V1
- 情感目标遵循**30 秒原则**和**溯源即信任**

### 给业务团队

- MVP 销售重点是**高保真溯源**（30 秒 vs2 小时）和**白标输出**（可直接交付）
- V1 销售重点是**多 Agent 辩论**（风险识别率≥90%）
- V2 销售重点是**完整合规**（SOX/ISO27001 认证）
