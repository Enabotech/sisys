## 1. MVP 目标与范围

### 1.1 MVP 核心目标

**时间周期：** 12 周（2026-03-01 ~ 2026-05-23）

**核心目标：** 验证单 Agent 战略规划核心价值，完成最小可行产品交付

**开发模式：** Qwen Code Agent + SDD（Specification-Driven Development）

**资源约束：**
- **人力：** 1 人
- **AI 助手：** 4~8 个 Qwen Code Agent 并行执行
- **开发范式：** AI 原生开发（AI-First Development）

**MVP 主题：** "Single Agent, Single Plan, Single Customer"
- 单 Agent 执行：验证一个 Agent 角色（CEO）独立完成战略规划
- 单规划流程：验证 BLM 模型部分阶段（市场洞察→业务设计）
- 单租户验证：验证基础多租户隔离（Basic tier，Row-Level 隔离）

### 1.2 核心功能列表（P0 级）

| 功能模块 | 功能描述 | 优先级 | 验收标准 |
|---------|---------|--------|---------|
| **单 Agent 执行** | CEO Agent 独立执行战略规划任务 | P0 | Agent 可完成 BLM 六阶段中至少 3 个阶段 |
| **基础 RAG 检索** | Dense+Sparse 混合检索，支持文档上传后的向量索引 | P0 | 检索延迟 P95<800ms，召回率≥80% |
| **BLM 部分阶段** | 市场洞察、战略意图、业务设计三阶段 | P0 | 每阶段可生成结构化输出并保存 Checkpoint |
| **Checkpoint 机制** | 单点恢复模式（Replay 模式） | P0 | 可从任意 Checkpoint 恢复执行 |
| **基础审计日志** | 关键操作记录审计日志（PostgreSQL） | P0 | 审计日志 100% 覆盖 P0 功能 |
| **文档上传解析** | 支持 PDF/DOCX/TXT 格式，自动向量化 | P0 | 文档处理成功率≥95% |
| **基础多租户** | Basic tier（共享 Schema+Row-Level 隔离） | P0 | 租户间数据 100% 隔离 |
| **白标输出基础** | 可配置租户 Logo 和主题色 | P0 | 支持 3 种预设主题 |

### 1.4 排除范围（MVP 不包含）

| 功能模块 | 排除原因 | 计划版本 |
|---------|---------|---------|
| 多 Agent 协作 | 复杂度高，MVP 聚焦单 Agent 验证 | V1.0 |
| BLM 完整六阶段 | MVP 验证核心价值即可 | V1.0 |
| BEM 业务执行模型 | 聚焦战略规划（SP） | V1.0 |
| 专业版多租户（Schema per Tenant） | Basic tier 满足 MVP 验证 | V1.0 |
| 完整审计日志（WORM 7 年） | MVP 阶段 PostgreSQL 存储即可 | V1.0 |
| CUSUM 漂移检测 | MVP 阶段基础监控即可 | V1.0 |
| Saga 事务一致性 | MVP 阶段单库事务足够 | V1.0 |
| Agent 沙箱（gVisor） | MVP 阶段 Docker 隔离足够 | V1.0 |
| REST API 接口 | MVP 阶段 CLI 接口足够 | V1.0 |
| 知识图谱（Neo4j） | MVP 阶段关系数据库足够 | V1.0 |

### 4.4 开发效率估算

**传统开发 vs AI 原生开发：**

| 指标 | 传统开发（6 人团队） | AI 原生开发（1 人+AI） | 说明 |
|------|---------------|---------------------|------|
| **代码生成速度** | 6 人 × 500 行/天 = 3,000 行/天 | 1 人 × 6 Agent × 400 行/天 = 2,400 行/天 | AI 略慢（需审查） |
| **代码审查时间** | 30% | 50% | AI 代码需要更多审查 |
| **Bug 率** | 15% | 20% | AI 生成代码 Bug 率略高 |
| **文档完整性** | 70% | 90% | AI 擅长文档生成 |
| **测试覆盖率** | 70% | 85% | AI 可快速生成测试 |
| **架构一致性** | 85% | 75% | 需要人类严格审查 |

**MVP 周期调整：**
- **原计划：** 6 人 × 8 周 = 48 人天
- **调整后：** 1 人 × 12 周 × 4 Agent 等效 = 48 人天（考虑 AI 效率提升和审查开销）

```python
from tenacity import retry, stop_after_attempt, wait_exponential, retry_if_exception_type

class LLMRetryWrapper:
    @retry(
        stop=stop_after_attempt(3),
        wait=wait_exponential(multiplier=1, min=4, max=10),
        retry=retry_if_exception_type((RateLimitError, TimeoutError))
    )
    async def call_llm(self, prompt: str) -> str:
        return await self.llm_client.generate(prompt)
```

**措施 3: 语义缓存**
```python
# src/infrastructure/cache/semantic_cache.py

class SemanticCache:
    SIMILARITY_THRESHOLD = 0.9
    TTL = 86400  # 24 小时

    async def get_or_compute(self, query: str, compute_fn: Callable) -> str:
        # 检查语义缓存
        cached = await self.search_similar(query)
        if cached and cached.similarity >= self.SIMILARITY_THRESHOLD:
            return cached.value

        # 缓存未命中，调用 LLM
        result = await compute_fn(query)

        # 写入缓存
        await self.set(query, result)
        return result
```

```python
        self,
        query_vector: List[float],
        limit: int = 10
    ) -> List[ScoredPoint]:
        # 使用 HNSW 索引加速检索
        results = await self.client.search(
            collection_name="documents",
            query_vector=query_vector,
            limit=limit,
            hnsw_ef=128  # HNSW 搜索效率参数
        )
        return results
```

**措施 2: 索引优化**

```sql
-- 创建 HNSW 索引
CREATE INDEX ON documents USING hnsw (embedding vector_cosine_ops)
WITH (m=16, ef_construction=64);

-- 创建 Payload 索引
CREATE INDEX ON documents USING gin (metadata);
```
