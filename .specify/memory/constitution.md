## 核心原则

### 文档驱动
所有开发工作必须以清晰的文档为先导。功能规范、实施计划、数据模型和API定义必须在编码开始前完成并获得批准。文档不仅是开发的指南，也是项目知识的载体，确保团队协作的一致性和可维护性。

### 测试驱动
采用测试驱动开发（TDD）方法论，所有代码必须伴随相应的测试用例。在编写功能代码之前先编写测试，确保代码质量和功能正确性。包括单元测试、集成测试和契约测试在内的多层次测试体系是保证软件可靠性的基石。

### 混合架构：六边形与事件驱动
采用经典六边形架构（端口和适配器）与事件驱动架构相结合的设计模式。六边形架构确保业务逻辑与外部依赖解耦，事件驱动架构支持系统的可扩展性和响应性。这种混合架构提供灵活性和可维护性，同时支持复杂的业务流程。

### Agents+LLM+Skills 插件支持
系统设计必须支持Agents、大语言模型(LLM)和Skills插件的集成。架构应提供标准化接口，允许灵活扩展AI能力和自动化工作流。这种设计使系统能够适应快速发展的AI技术，为用户提供智能化解决方案。

### Qwen Code 主导开发与人工监督
采用Qwen Code作为主要开发工具，结合人工审核监督确保代码质量和项目方向。AI辅助提高开发效率，人工审核保证代码符合架构原则和业务需求。这种人机协作模式平衡了开发速度与质量控制。

## 开发工作流

Qwen Code主导的开发工作流包括以下阶段：需求分析、功能规范制定、实施计划、任务分解、编码实现、测试验证和部署。每个阶段都有明确的交付物和质量标准，确保项目按计划推进。

## 质量标准

所有代码提交必须通过静态分析、单元测试和集成测试。代码审查是合并到主分支的必要条件。质量门控包括代码覆盖率、性能基准和安全扫描，确保交付高质量的软件产品。

## 治理

宪法是项目开发的最高准则，所有技术决策和开发活动必须符合宪法原则。对宪法的任何修改都需要充分讨论、文档记录和团队批准。
